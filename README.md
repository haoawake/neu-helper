# NEU Helper

开机自动弹出的 Canvas 学业桌面应用:左边是仪表盘(DDL / 成绩 / 公告),右边是
每日简报和对话。同时把 Canvas 接成 MCP,让你在**任何** Claude Code 会话里都能
直接问课程、作业、成绩、公告。

Canvas 实例:`northeastern.instructure.com`(可配置,见 [canvas_api.py](canvas_api.py))
平台:**Windows 和 macOS 都能跑**(同一份代码,原生那一层分了两套实现 ——
见[双端是怎么分的](#双端是怎么分的))。

---

## 装哪个版本

| | 怎么拿 | 要不要装 Python |
|---|---|---|
| **Windows 打包版** | [Releases](https://github.com/haoawake/neu-helper/releases/latest) 下 `NEU-Helper-win-x64.zip`,解压后跑一次 `setup.ps1` | **不用** |
| **macOS 打包版** | 没有现成的,在 Mac 上 `./packaging/build_mac.sh` 自己构建一次 | 构建时要 |
| **源码版(两个平台)** | `git clone` 之后 `./install.sh` / `install.ps1` | 要(3.9+) |

macOS 没有现成包**不是偷懒**:PyInstaller 冻结的是它运行那台机器的解释器和
原生库,所以 mac 的包没法在 Windows 上做。`.spec` 是两端共用的,那条命令跑完
就是一个能用的 `.app`。不想折腾打包的话,macOS 上直接用源码版更省事。

打包版和源码版的**唯一功能差别**:两个课件技能会去调 `python`,打包版没带
解释器,所以那两个辅助脚本用不了。搜课件本身照样能用(助手直接 grep 同步下来的
`.txt`)。

第一次打开前记得**改 `CLAUDE.md` 里的课程对照表** —— 那份是从
`CLAUDE.example.md` 复制来的模板,不改的话简报会讲错课。

## 怎么打开

**双击桌面上的「NEU Helper」**(玻璃球图标)。没有控制台、没有黑窗闪一下。

其余几条路都通到同一个地方:

| 方式 | Windows | macOS |
|------|---------|-------|
| 桌面上那个 | 快捷方式 → `pythonw app.py` | `~/Desktop/NEU Helper.command` |
| 项目里双击 | [launch.vbs](launch.vbs) | [NEU Helper.command](NEU%20Helper.command) |
| 开机自动 | 启动文件夹的快捷方式 → [startup-gate.vbs](startup-gate.vbs) | LaunchAgent → [startup-gate.sh](startup-gate.sh) |
| 命令行 | `pythonw app.py` | `python3 app.py` |

开机那一条两边都是**每天只开一次**。

**只会有一个实例。** app.py 一启动就去抢一把锁,已经在跑的话第二次启动只把原来
那个窗口叫到前面,然后自己退掉。所以重复双击、开机闸门、手动打开撞在一起都不会
开出两个。两边用的机制不同但都选了"进程死了自动释放"的那种 ——
pid 文件那种做法会在崩溃后留一把锁,下次就再也起不来了:

| | 机制 | 为什么 |
|---|---|---|
| Windows | 命名互斥体 `Local\NEUHelperSingleton` | 内核维护,进程怎么死的都会自动释放 |
| macOS | `~/.canvas-helper/NEUHelper.lock` + `flock` | 同样内核维护,进程退出时描述符一关锁就没了 |

把已经在跑的那个叫到前面,两边也不一样:Windows 直接 `FindWindowW` + `ShowWindow`;
macOS **不能去动别的进程的窗口**,只能用 AppleScript 让系统激活那个应用。

**别手动跑那个开机闸门**(`startup-gate.vbs` / `startup-gate.sh`)—— 它带
"今天开过就不开"的判断,手动双击经常是静默什么都不发生。那两个文件只给开机用。

窗口找不着了?可能收成了悬浮球(屏幕右下角那颗小玻璃球,单击弹对话框),
也可能最小化到任务栏了。

### 另外两种用法

**1. 开机自动打开(每天第一次开机)**
无控制台、无闪窗,直接出应用窗口。仪表盘立刻有数据(纯 Canvas API,零模型消耗),
简报按下面的规则生成。

**2. 任何会话里直接问**
在任意目录跑 `claude`,然后直接问「我这周有什么要交的」「CS5800 PA1 要求是什么」
「DS5110 成绩现在多少」。

终端版还留着,想要纯文字的时候用:`.\start-canvas-helper.cmd`
(注意它跑的是老的 `brief.py` + `claude boot-briefing` 那套,**不是**桌面应用。
这个只有 Windows 版 —— macOS 上直接 `python3 brief.py`。)

## 窗口三态

窗口是**无边框**的,标题栏、拖拽、最小化、关闭都是自己画的。三种形态:

| 形态 | 尺寸 | 内容 | 置顶 |
|------|------|------|------|
| **悬浮球** | 默认 36px(设置里 26–72 可调) | 一颗透明玻璃泡,里面有光晕在流转;有逾期项时右上角一个数字角标 | 是 |
| **对话框** | 400×620 | 只有 AI 对话 | 看设置 |
| **完整面板** | 1180×780 | 仪表盘 + 简报/对话 | **否** |

置顶的规则:完整面板**从不**置顶(它那么大,压着别人没法干活);对话框那一态
默认置顶(那一态本来就是"浮在别的窗口上问两句",可以在设置里关掉)。想让任何
形态都压在最上面,点标题栏那个 **📌 大头针**。

怎么走:

- 悬浮球 **单击** → **还原成收起来之前那个形态**(从完整面板收的就还原成完整
  面板);**双击** → 不管之前是什么都展开完整面板;**右键** → 小菜单
- 标题栏 **双击** → 没展开就展开,已经是完整面板就最大化 / 还原
- 对话框标题栏的 **⤢** → 完整面板
- 完整面板的 **▭** → 收成对话框,**○** → 直接收成悬浮球
### 收成球会记住"收之前长什么样"

点球回来不是"弹一个标准尺寸的窗口",是**原样还原**:收之前铺满全屏就还回全屏,
拖到哪儿、拉成多大,回来都一样。收球时存三样进 `data/prefs.json`:

| 存的东西 | 干什么用 |
|---|---|
| `restoreMode` | chat 还是 full —— 决定页面排哪套布局 |
| `restoreRect` | 整个矩形 `[x, y, w, h]` |
| `restorePreExpand` | 再上一层:**展开之前**那个矩形 |

第三项容易漏。没有它的话,"从全屏收球 → 点球回到全屏 → 双击还原"会跳到一个
从没见过的默认尺寸 —— 因为"展开前是多大"只活在内存里,收球那一下就丢了。

存下来的矩形不是照搬回去:中间可能过了一整天,分辨率变了、副屏拔了。
但**也不能夹进工作区** —— 窗口比工作区高、故意伸出底边是很常见的用法,
硬顶上去等于替用户改了布局(第一版就把一个 y=235 的窗口顶到了 151)。
现在只保证两件事:标题栏够得着,横向至少留 120px 在屏幕上。

### 收放是怎么做到不断点的

难点在于这是**两个窗口**:面板是 WebView2,球是自己画的分层窗口。中间那一下
换手很容易露馅。

第一版就露了:窗口收到 170px 就停,然后 46px 的球凭空弹出来 —— 尺寸差 6 倍、
形状从圆角方跳成圆,怎么看都是"两个东西"。

现在的做法是**让它们在某一刻完全重合,再交叉淡化**:

1. 页面先把内容淡掉(110ms)。原生窗口是逐帧 `SetWindowPos`,每帧 WebView2 都要
   重排一次;不遮住的话那串中间布局全看在眼里,读起来是"抽了一下"
2. 同时页面背景换成球的样子(`body.is-orbing`:左上高光 + 中间蓝紫光晕 +
   贴边亮环),所以缩下去的过程中看到的就是一颗球在变小
3. 窗口一路缩到**球本体**那么大、那么位置(不是整张画布 —— 画布外圈是透明的
   投影边距,对不上球会"跳"一下)。同时整窗 alpha 降到 50%,圆角方的四个角
   就不显眼了
4. 130ms 交叉淡化:窗口 50%→0,球 0→100%。此刻两个窗口同位置同大小,
   差别只有四个角几个像素,看不出来
5. 藏掉窗口、把整窗 alpha 还原成设置里的值

展开就是倒过来放。

实测(`GetWindowRect` + `GetLayeredWindowAttributes` 每 10ms 采一次):
收起 2065px → 46px 连续 34 帧 / 700ms,两个窗口重合了 140ms;
展开 650ms。收完之后窗口和球的**球心矩形完全一致**(都是 46x46 @1346,1193)。

窗口那头的淡化用 `WS_EX_LAYERED` + `LWA_ALPHA`(和设置里的「整窗透明度」同一个
机制),球那头用 `UpdateLayeredWindow` 的整体 alpha。两边都只是改一个数,
没有额外重绘。

### 悬浮球是**另一个窗口**

不是网页画的。**`SetWindowRgn` 裁不住 WebView2** —— 窗口区域只约束 GDI 绘制,
而 WebView2 的画面是 DirectComposition 的视觉层,由 DWM 直接合成、不看窗口区域。
实测:窗口缩到 136×136、贴上椭圆区域,`GetWindowRgnBox` 确认区域生效
(COMPLEXREGION),但屏幕上仍然是一个**白色圆角方块**,球装在方块里 ——
这就是之前那个「矩阵白边」。

所以球改成 [orb_window.py](orb_window.py):自己算一张 32 位 BGRA 位图,用
`UpdateLayeredWindow` 贴上去(逐像素 alpha)。好处是连着的:

- 真圆、边缘抗锯齿、有真正的投影
- **收成球时整个 WebView 窗口 `SW_HIDE`**,实测这一态下 WebView 那边的 CPU 是
  `0 ms / 6s`(渲染进程跟着一起歇了)
- 拖动是这个窗口自己的 `SetCapture`,不掺和 Chromium 那边的鼠标捕获

### 球长什么样:一个透明玻璃泡

关键是 alpha 的分布,不是颜色:

- **球心 alpha 只有 0.18**,所以中间是真的能看见桌面
- alpha 沿 `(dist/r)^4` 往外涨到 0.80,边缘那圈亮环很窄 —— 轮廓立得住,
  中间还是透的
- 内部两团光(蓝 + 紫)绕着球心转,**既加颜色也加 alpha**:光走到哪儿那块就
  "厚"一点,看起来像里面有液体在流
- 左上一小块强镜面高光 + 下缘内反光,负责"这是个球"这件事

光晕是 24 帧相位**预渲染**好、靠 `WM_TIMER` 轮播的(9fps,约 2.6 秒转一圈)。
逐帧现算不行 —— 一帧十几毫秒,而且是在窗口过程里算,会把消息循环拖住。
代价是这颗球开着表大约占 **2% 一核**(每帧一次 `UpdateLayeredWindow`,
DWM 要重新合成一遍);设置里关掉「过渡动画」就冻在第 0 帧、定时器也不留。

**hover 是 0.5 秒的缓动**,不是一放上去就换脸:整体提亮 + 变大 5% +
抬起 2px + 光晕转速加倍,四件事一起渐变过去。

- 目标状态只由 `_set_hover` 记一下,真正的变化由定时器每拍推进一点
  (`_hlevel` 朝 0/1 缓动,smoothstep)
- 静止帧和 hover 帧之间用 GDI 的 **`AlphaBlend`** 在一张暂存位图上交叉淡化 ——
  逐像素插值在 Python 里跑不起(一万个像素一帧十几毫秒),AlphaBlend 是原生的
- 过渡期间定时器跳到 26ms(≈38fps),稳定之后降回去省电
- 光晕的推进按**时间**算(`dt / 周期`)而不是按拍数,否则定时器一变快、
  光晕就跟着变快
- 鼠标离开靠 `TrackMouseEvent` 的 `WM_MOUSELEAVE` 收场

实测抬升的两级出现在 171ms 和 436ms(进),263ms 和 511ms(出)。

预渲染总成本:默认尺寸约 500ms(6 缩放帧 + 24 相位帧 + 8 hover 帧),
在球自己的线程上跑,不挡启动。

球被夹在工作区里(屏幕减掉任务栏),所以不会被拖到任务栏底下、也不会收起来时
正好落在屏幕外面 —— 那种情况它既看不见也点不着。

### 阴影不能被位图边界切断

第一版的投影很明显是个方块。衰减是 exp(-d/spread) 没错,但位图只有
 大 —— 到边界时 alpha 还剩 5% 左右,然后被硬生生截断,
四条边各留一道直线。

现在两处改动:pad 从直径的 0.28 倍放到 0.36 倍(给阴影留地方),
再乘一个**圆形**的收尾(到位图内切圆处正好归零)。实测最外一圈的 alpha
全是 0,离边 1px 是 2~5/255 —— 看不出边。方形的收尾解决不了这个问题,
因为方形收尾本身就是方的。

### 拖窗口:为什么不用 `WM_NCLBUTTONDOWN`

原来想省事:后端发一条 `WM_NCLBUTTONDOWN` + `HTCAPTION`,Windows 自己进移动
循环。**实测一下都拖不动。** 那个循环起手要 `SetCapture`,而鼠标捕获此刻在
Chromium 的渲染子窗口手里(另一个进程,`ReleaseCapture` 也管不着),抢不到捕获
就立刻退出。

现在是自己跟光标:前端 `pointerdown` 记起点、`pointermove` 每帧发一条
`/api/window/drag/move`(rAF 合并,最多 ~60/s),后端每次自己 `GetCursorPos`
算位移。**前端一个坐标都不传** —— `screenX` 是 CSS 像素、窗口要物理像素,
这个换算在多显示器 + 175% 缩放下很容易算错,干脆绕开。

形态、主题、球的大小和位置都记在 `data/prefs.json`,重启照旧。

### 标题栏:一个按钮管两个方向

「展开完整面板」和「收成对话框」本来是两个按钮,靠 CSS 各藏一个 ——
占两个位置、两套接线,而它们是同一件事的两头。现在合成一个 `#btnSize`,
图标和说明跟着形态走(完整面板时 `▭ 收成对话框`,对话框时 `⤢ 展开完整面板`)。
收成球的时候按对话框算 —— 球里面的页面本来就是按对话框排的。

对话框只有 400px 宽,标题栏里还要塞下品牌名、副标题、学业/邮箱、五个图标。
品牌名 `white-space: nowrap` 又不肯缩,于是直接压到分段选择器上 ——
那就是"标题和学业/邮箱重合"的原因。窄态把品牌名和副标题都藏掉:
那个尺寸下它们没有信息量(副标题还会截成「Ziha…」这种半截字),
留一个圆点当拖拽把手就够。分段选择器标了 `flex: 0 0 auto` 绝不压缩 ——
它是个操作,品牌名才是可牺牲的那个。

## 划掉不想管的 DDL

每张待办卡片左边有个空心圆,**点一下就划掉**:标题横一道线划过去、整卡淡化。
划掉之后这一项:

- 退出所有统计(未提交待办数、待拿分值、hero 倒计时、逾期告警)
- **不再写进 `data/snapshot.md`,所以以后的每日简报也不会再提它**
- 仍然留在列表里,圆圈变成蓝色打勾 —— 再点一下就撤回

标识用的是 Canvas 的 `plannable_id`(不是标题),所以教授改个作业名也不会让
忽略失效。记录在 `data/dismissed.json`。

底栏会显示「已划掉 N 项(不计入简报)」,提醒你有东西被藏起来了。

## 设置

标题栏的 **⚙**(或者 `Ctrl+,`)。分三栏 —— **通用 / Canvas / 邮箱**,
按"改的是什么"分,不按"哪个模块实现的"分。每一项都直接写进 `data/prefs.json`。
关面板时停在哪一栏会记住。

### 通用 —— 长什么样、怎么摆

| 项 | 说明 |
|---|---|
| 主题 | 跟随系统 / 浅色 / 深色。悬浮球的配色也跟着换 |
| 玻璃模糊 | 0–44px。**0 会把 `backdrop-filter` 整条去掉**(写 `blur(0)` 没用,那样仍然要建一层滤镜) |
| 表面不透明度 | 30–100%。页面里玻璃板自己的底色。所有玻璃色都是从 `--glass-a` 算出来的,所以拖滑块即时预览 |
| 整窗透明度 | 55–100%。**真的透到桌面** —— `WS_EX_LAYERED` + `LWA_ALPHA`,DWM 在合成时整窗混色。代价是文字也跟着变透 |
| 过渡动画 | 关掉等于系统那个「减少动态效果」 |
| 悬浮球直径 | 26–72px |
| 对话框保持在最前 | 只管对话框那一态;完整面板从来不置顶 |

按钮:把球放回右下角、现在就收成球、打开数据目录 / 启动文件夹。

### Canvas —— 数据口径和简报

| 项 | 默认 | 说明 |
|---|---|---|
| 播报时刻 | 9 点 | 一天仍然只发一次 |
| 带几天历史 | 3 份 | 简报的价值在于说变化,所以把前几天的原文一起给模型。带得多判断更准,prompt 也更长 |
| 待办往后看 | 28 天 | `/planner/items` 的窗口 |
| **几天内算紧急** | 3 天 | **一个数决定所有状态标签**:紧急 = 它以内,临近 = 它的两倍以内,再往后充裕 |
| 公告往前看 | 10 天 | 改 DDL、调课、考试通知都藏在公告里 |
| 重点课程 | 空 | 一行一个课程简称。填了之后简报优先盯这几门,其他课除非有硬截止否则一句带过 |
| 列出划掉的条目 | 开 | 关掉之后划掉的条目从列表里彻底消失(存档还在,可以全部恢复) |
| 自动同步 / 单文件上限 | 开 / 80MB | 见「课件自动同步」那一节 |

按钮:立即生成今天的简报、全部恢复划掉的条目、立即同步、打开课件目录。

> 「几天内算紧急」这一条以前是**存了但不生效**的 —— 阈值收进函数了,函数体里
> 的 1/3/7 还是硬写的。存了却不生效的设置比没这个设置更糟:你会以为自己
> 已经调过了。现在两档都从它派生。

### 邮箱 —— 我是谁、什么算重要、盯着什么

| 项 | 说明 |
|---|---|
| 我的情况 | 一行一条事实(名目 + 内容),进 AI 过目**和**邮件简报 |
| 读过就同步已读 | 唯一会改动邮箱的开关(只动 `\Seen`) |

### 面板里为什么没有说明文字

设置面板只放控件,不放讲解 —— 25 段、1863 字的说明把一个改参数的地方
变成了一篇读物。唯一的例外是 QQ 授权码那几步:那不是讲解,是照着做的操作步骤,
不写就配不上账号。

有区分度的信息(哪个透明度透到桌面、「临近」怎么从「紧急」算出来、
「全部重判」要花钱)收进了控件的 `title`,鼠标停上去还看得到。
原理和踩过的坑都在这份 README 里。

### 落盘的时机

滑块是 `input` 事件预览、`change` 事件落盘 —— 拖一次不会写几十遍文件。
文本框(重点课程、「我的情况」那几行)更小心一点:**打字时不写盘**,
停手 0.8~1.2 秒或者失焦才写,关面板时也会先把没落的那一笔补上。每次 `savePrefs`
都要重刷整个面板,正在打字的时候那会打断输入法。

同一个原因,`renderFacts()` 在**焦点还在里面的时候不重建** DOM ——
重建会把光标顶走。

**这条规则咬了我两次,两次都是"用户自己点的动作也被当成顺带重绘挡掉了"**:

1. 「加一条」原本是"发请求 + 立刻聚焦最后一行",但聚焦跑在重绘之前,焦点落到了
   **旧的**最后一行上,于是重绘被挡住 —— 新行画不出来,接着打的字还进了上一行
2. 「删一条」点的那个 ✕ **就在 `#factList` 里面**,点它的时候焦点正落在它身上,
   重绘同样被挡住 —— 盘上确实删了,屏幕上那行不动,看起来就是"删不掉"

所以现在分开:`renderFacts(force)` —— 增删传 `force`,一定重绘;
不带 `force` 的才是顺带重绘(SSE 推回来、`syncPrefsUI`),那种才让焦点。

第二个坑后面还藏着一个更隐蔽的:DOM 没重绘,**行的位置和数组下标就对不上了**。
每行的提交回调闭包里捏着渲染时的 `i`,删掉中间一行之后再改下面任何一行,
写进去的是错的那一条。所以"用下标认行"整个去掉了 —— 提交时用
`collectFacts()` 从 DOM 现读一遍整个列表,压根不需要下标。

偏好写完后端会顺着 SSE 推一条回来,所以手改 `data/prefs.json` 界面也会立刻跟上。

### 「表面不透明度」和「整窗透明度」的区别

前者是 CSS:玻璃板的底色变淡,透出来的是**页面自己的背景**(那层柔光渐变)。
后者是 DWM:整个窗口连文字一起半透明,透出来的是**桌面和背后的窗口**。

想要"透到后面"只能用后者。`backdrop-filter` 碰不到桌面,pywebview 的
`transparent=True` 在这台机器上也不生效(页面设 `background:transparent`
之后背后仍是一块不透明浅灰)。

顺带记一笔:DWM 的磨砂背板这条路走不通。`SetWindowCompositionAttribute` 的
`ACCENT_ENABLE_ACRYLICBLURBEHIND` 和 `DwmSetWindowAttribute` 的
`DWMWA_SYSTEMBACKDROP_TYPE` 两个接口**都返回成功**,但屏幕上背后的内容依旧
清晰(截图比过)。所以"透到桌面"是有的,"把桌面磨砂"没有。

## 双击展开:为什么不用系统的最大化

双击标题栏是**自己动画到工作区**,不是 `ShowWindow(SW_MAXIMIZE)`。

系统的最大化一帧到位,在这个应用里是唯一一处瞬移 —— 别的形变全是逐帧插值的。
而且**没法给它补动画**:窗口处于 zoomed 状态时 `SetWindowPos` 只改"还原后的
尺寸",屏幕上纹丝不动。所以干脆不用它:

- 展开 = 记下当前矩形,动画到**这块屏幕**的工作区(`MonitorFromWindow` +
  `GetMonitorInfoW` 的 `rcWork`,不是 `SPI_GETWORKAREA` —— 后者只认主显示器,
  窗口拖到副屏上双击会飞回主屏)
- 还原 = 动画回记下的那个矩形
- 状态判断看"矩形有没有铺满工作区",不看 `IsZoomed`
- 别处真遇到 zoomed(用户按了 Win+↑)时,`unzoom()` 先脱掉这个状态、
  同时把矩形贴回原处 —— 状态换了但屏幕上不动,后面的动画才看得见

动画在后台线程跑,HTTP 接口立刻返回(实测 12~22ms),不然双击一下要等
260ms 才有反应。决策和"记下展开前的矩形"在一把锁里做完:连点两下的话,
第二下不能把动画到一半的矩形当成原始尺寸记下来。

实测:2065 → 2560 走了 16 个不同宽度,回来 15 个,正好回到展开前那个矩形。

## 备忘录

右栏(简报 / 对话 那一栏)的**第三个标签**,学业页和邮箱页都有。四种备忘:

| 类型 | 显示成 |
|---|---|
| 纯文字 | 只有文字 |
| 某一天 | 大号 `4 天 22 小时 47 分钟`,上面一个小字「还剩」/「已过」 |
| 每周某天某点 | 同上,后面挂一个「第 3 周期」 |
| 每月某号某点 | 同上 |

**有时间的备忘,时间是主角**:大号数字在上、备忘内容退成下面的副标题。
没时间的那种就只有一行文字,自然退到次要位置。到点了的左边一道红线,
24 小时内的一道橙线。

**倒计时是后端算的。**「下一次什么时候」「这是第几个周期」必须有一处权威答案,
不然周期号会随着页面什么时候打开而漂。前端每 30 秒重取一次。

每月 31 号这种要小心:遇到 2 月会落到月底(28/29),不是崩掉也不是跳过。

### 一份 DOM,两个侧栏轮流用

学业页和邮箱页是互斥的两棵子树,而备忘录的界面只该有一份。做法是
**把 `#panelMemo` 这个节点在两个侧栏之间搬**(`appendChild` 是搬不是拷)——
一份 DOM、一套接线,不会出现两份状态不同步。

### 拖过来直接建一条

把作业、公告、邮件、课件**拖到「备忘录」那个标签上**(不用先切过去),
自动生成一条,建完自动切过去让你看见。作业带截止时间的**直接做成"某一天"**
那种 —— 那个时间点本来就是它的意义(从 `2026-09-23 23:55 太平洋夏令时`
这种给人看的串里把时间抠出来)。备忘会记着来源,能一键点回原处。

### 列表不许有入场动画

这个列表会被反复重画:点完成、SSE 推回来、倒计时到点。卡片上挂入场动画的话
每次重画都重放一遍,看起来就是**一直在闪**。所以 `.memo-item` 没有 animation。

光去掉动画还不够 —— 点一次"完成"原本会重画**两次**:自己渲染一次,
后端 `push_memos` 的 SSE 回来又一次。现在自己改完打一个时间戳,
SSE 那条 2.5 秒内看到是自己干的就只更新角标、不重画。实测点一次重画 1 次。

### 悬浮球停一秒,弹一条备忘录窄栏

鼠标停在球上超过 1 秒,主窗口变成一条窄栏贴着球弹出来,里面只有备忘录
(同一个 `#panelMemo`,搬到 body 底下铺满)。指针移开就收。

收起来的判断比想象的绕,**踩了两次**:

1. 光靠球的 mouse-leave 不行 —— 指针往往正是"移到浮窗上"才离开球的,
   那时候收起来就没法用了。所以起一个看门线程,把球和浮窗两个矩形并起来看,
   指针连续在外面 600ms 才收
2. 在浮窗里**点日期选择器**,窗口自己关了 —— 系统的选择器是**另一个弹出窗口**、
   落在浮窗外面,指针跟着过去,看门线程就认为人走了。现在两道防线:
   浮窗是前台窗口时不收,而且页面在开表单时会显式"钉住"

## 信息弹窗

Canvas 有新作业/新公告、或者来了新邮件,右下角弹一条横条(设置 → 通用 →
信息弹窗,能关、能改停留秒数、能「试一条」)。点它把应用叫回来。

**新邮件报的是 AI 写的那句摘要**,不是主题 —— 所以会等过目跑完再弹
(最多等 90 秒)。等不到就退回主题。那和系统通知的区别就在这一句:

```
新邮件 · Chen, Alex
[学业] 邀请填写 Research Rush 兴趣表单,截止 9/21 周一 10 点前完成。
```

Canvas 那边比的是**见过的 id**,不是时间戳:改一次截止时间不会换 id,
那种变化不该当成新东西反复弹。第一次启动只记账不弹 ——
不然一装上就把 20 条存量作业全弹一遍。

**跟着应用的主题走,不是跟着系统。** 弹窗是启动时建好一直留着的,主题可能
后来才改 —— 所以每次弹之前重读一遍 `dark_mode()`(它先看应用的 `theme` 偏好,
`auto` 才去问系统注册表)。少了这一步,深色模式下弹出来是一张白板。

### 为什么是自绘的原生窗口

它要在应用收成悬浮球、甚至窗口完全隐藏的时候照样弹,所以不能是页面里的一个
div。Windows 10 的系统通知要 WinRT(不在标准库里),而这个项目的硬约束是零
第三方依赖 —— 所以走和悬浮球同一条路:`WS_EX_LAYERED` + `UpdateLayeredWindow`,
GDI 画圆角底 + `DrawTextW` 排文字。`WS_EX_NOACTIVATE` 保证它弹出来不抢焦点,
正在打字不会被打断。

### 文字是透明的洞

第一版弹出来是"文字全部看不清",桌面从字里透出来。原因:**GDI 在 32 位 DIB
上画字不写 alpha 通道,而且会把字形像素的 alpha 清零。** 用 `ULW_ALPHA` 合成时
那些像素就是完全透明的洞。

所以画完字必须**把 alpha 按原来的遮罩补回去**:建底的时候留一份 alpha
遮罩,画完文字再把卡片内部那些补回 255。圆角和阴影上没有字,不用动。

### 外阴影不能直接截断

**外阴影**是把位图往外放 20px,那一圈按到圆角矩形的距离算 `exp` 衰减,
阴影中心往下偏一点,卡片才像"浮"着。

但光有 `exp` 不行:衰减到位图边界时还剩 6% 左右的不透明度,**那一刀切下去
就是一圈方角** —— 看上去弹窗底下垫着个方块。所以再乘一个到边界正好归零的
平滑窗(`(1-t)²`,`t` 是到边界的归一化距离),外圈才真的化掉。

实测这一圈的衰减:`0px→76, 6px→21, 12px→4, 19px→0, 25px→0`。
**这和悬浮球的投影是同一个坑**,那边用的是圆形淡出,道理一样:
自绘阴影必须自己保证在位图边界上归零,没人会帮你做这件事。

### 两个 ctypes 的坑

**一、`UpdateLayeredWindow` 和 `SetLayeredWindowAttributes` 是互斥的。**
前者逐像素 alpha,后者整窗常量 alpha。我用前者画、又用后者做淡入淡出,
结果是画完就被擦掉:窗口"可见"、位置也对,屏幕上空的。淡化要走
`BLENDFUNCTION.SourceConstantAlpha` 再贴一次 —— 所以位图和 DC 得跨调用留着。

**二、给共享 API 设 argtypes 会串味。** `ctypes.windll.gdi32` 每次拿到的是
同一个对象,上面的函数对象也是缓存的。`toast.py` 里把
`CreateDIBSection.argtypes` 设成 `POINTER(toast.BITMAPINFOHEADER)`,
就把 `orb_window.py` 设的那份(指向它自己的同名结构体)**顶掉了** ——
后 import 的赢,另一个运行时直接炸:

```
expected LP_BITMAPINFOHEADER instance instead of pointer to BITMAPINFOHEADER
```

表现是**悬浮球完全画不出来**,而且只在两个模块都被 import 时才复现。
现在两边的结构体指针一律声明成 `ctypes.c_void_p`:`byref()` 出来的东西它照样收,
而且不绑定具体是哪个类。

## 动作规范

整份样式按三条自律来,新加东西也照这个走:

**只动 `transform` 和 `opacity`。** 这两个属性走 GPU 合成,不触发重排重绘。
刻意不给 `box-shadow` / `backdrop-filter` / `width` / `height` 加 transition ——
那些每帧都要重绘,是这类界面最常见的卡顿来源。(审计过:全份 CSS 里没有一条
给重绘属性加 transition。)

**缓动按用途分,不是随手挑一条。**

| 场景 | 曲线 | 为什么 |
|---|---|---|
| 进场 | `--ease-decelerate` 快起慢收 | 东西"飞进来"然后稳住 |
| 离场 | `--ease-accelerate` 慢起快走 | 走的时候不拖沓 |
| 位置移动 | `--ease-standard` 两头慢 | 一整块东西在挪,起停都要软 |
| 球、浮层 | `--ease-spring` 轻微过冲 | 只给"物件",给面板会显得廉价 |

**时长分三档**:120ms 微交互(hover / 按下)、200ms 进场、280ms 位置移动。
超过 300ms 的只有窗口形变(那是真有一大块东西在动)和 hover 那 0.5 秒的缓动。

具体清单:子页面切换(淡入 + 8px 横移)、课程单页进出、卡片错开 16~24ms 逐个
浮现、成绩 meter 从左生长、标签下划线伸展、消息浮现、删除线从左划过、
按钮按下回弹、球的光晕流转和 hover 缓动、窗口三态形变 + 交叉淡化、
双击展开/还原。

### 收球时"什么时候变成球"是按宽度判的,不是按时间

收球的时候页面要画成球的样子,那最后 130ms 的交叉淡化才看不出换了个窗口。
问题是**什么时候开始画**。

这里错过两次。第一次把球画成百分比渐变 —— 在 2065px 宽的窗口上就是一个铺满
全屏的大球。第二次改成固定 120px,但 `background-color` 直接给了 `body`,
于是 t=0 整扇窗瞬间变成一块淡蓝色板子:读起来还是"页面先变成球、然后才缩",
顺序反的。

第三次先试了"延迟 300ms 再淡入"。看着对,一量就露馅:从**最大化**状态收球,
380ms 时窗口还有 500px 宽 —— 同样的 340ms 动画,起点不同,中间尺寸完全不是
一回事。按时间对齐从根上就是脆的。

现在按**窗口实际宽度**驱动。页面就在窗口里面,`window.innerWidth` 就是窗口有
多宽,rAF 每帧读一下写进 `--ball-a`:宽过 `max(220, 直径×6)` 完全看不到球,
窄到 `直径+14`(球那个窗口比球本身大一圈,是软阴影的余量)完全是球。
既不用后端推进度,也不用两边对时长;展开是同一条曲线反着走。

实测收球:2065px 全程看不到球,204px 时开始露头,58px 时基本满,
到 46px 正好 1.0 接上交叉淡化。

系统开了「减少动态效果」或者设置里关了过渡动画,全部停掉。

### 顺手打磨的几处

- **滚动条**:细条、无箭头、悬停才明显(默认那条又宽又抢眼)
- **键盘焦点**:`:focus-visible` 一圈 accent 描边 —— 鼠标点击不出现,
  只有 Tab 走过来才有
- **长列表** `contain: layout style`:改一条不让整栏重新算布局

## 空闲时它到底费不费电

**一整套(python + WebView2 全部子进程)空闲 0 ms / 10s。**

这个数字是改出来的。SSE 那条长驻连接原来固定 80ms 轮询一次、把四条通道都
drain 一遍 —— 空闲时一天要醒一百多万次。现在**自适应**:有人在说话(发过消息
或者正在流式)就 80ms,安静 2 秒以上退到 400ms。发消息的接口会打一个"热"标记,
所以第一个 token 的延迟没变大。

其余几处的节流:
- 悬浮球的光晕只在球**可见**时开定时器(9fps),收起来就 KillTimer
- 课件同步每小时一次,增量 —— 没变的文件一个字节都不传(实测第二次 2 秒、零流量)
- 邮箱 3 分钟一轮,只取信头 + 700 字摘要,不下附件
- 课程视图缓存 5 分钟(一次视图要 4~5 个 Canvas 请求)
- 仪表盘有缓存,`force=1` 才真的重拉

## 液态玻璃 · 以及为什么不卡

界面是半透明玻璃叠在一层柔光渐变底上。有两条硬约束:

### 模糊需要背后有高频细节

第一版的滑块"拖了没区别":`backdrop-filter` 只模糊背后的东西,而背后是一层
柔光渐变 —— 低频图像糊 8px 和糊 44px 出来几乎一模一样。

所以底层现在故意加了**硬边**的细节:三个实心圆 + 一组 2px 的细斜纹。
这些是高频的,模糊半径一变立刻看得出来。全部是静态 `background-image`,
零运行时开销。

**`backdrop-filter` 只加在几个大容器上**(标题栏、左栏、右栏、作业详情浮层)。
卡片数量多,一律用「半透明底色 + 顶部内高光」模拟玻璃 —— 视觉差别很小,
开销差一个数量级。底层那三团柔光是静态 `radial-gradient`,零运行时成本。

**动画只碰 `transform` 和 `opacity`**,走 GPU 合成,不触发重排重绘。
刻意不给 `box-shadow` / `backdrop-filter` / `width` 加 transition ——
那些每帧都要重绘,是这类界面最常见的卡顿来源。

动画清单:窗口形变(原生逐帧 + 内容淡出遮盖)、悬浮球缩放回弹入场(位图预渲染
6 帧,窗口尺寸不动)、卡片错开 24ms 逐个浮现、成绩 meter 从左生长、标签下划线
伸展、面板切换淡入、消息浮现、删除线从左划过、按钮按下回弹。

### 流式输出为什么会「每秒闪一次」

markdown 是块级结构,没法只追加,所以每来一段增量都要把简报/回答那块 DOM
整体重建一次。原来是**收到就重建**:一秒来两三段就重建两三次,而重建出来的
元素会**重放入场动画** —— 看起来就是界面每隔一下刷新一下。

两处改动:增量渲染合并到一次 `requestAnimationFrame`(一帧最多重建一遍),
渲染期间给容器挂 `.streaming` 把入场动画全部关掉,写完再摘掉。
另外流式光标原来是 `blink 1s step-end infinite`,它就待在一个带
`backdrop-filter` 的大容器里,每次 opacity 翻转都会让整块模糊区域重算 ——
现在是个不闪的方块。`background-attachment: fixed` 也去掉了,同样的道理。

空闲状态实测:零请求、渲染进程 0.3% 一核、像素零变化。

系统开了「减少动态效果」会全部关掉 —— 前庭敏感的人看这些会不适。

## 课件自动同步到本地

**Canvas 上能看到的文件,全部自动下到本地并且分门别类**,由
[filesync.py](filesync.py) 负责:启动后同步一次,之后每小时一次。
增量 —— 只下新的和改过的。

```
data/downloads/
  index.json                    所有文件的索引(课程 / 分类 / 路径 / 大小 / 时间)
  DS5110/
    _课程概览.md                作业 + DDL + 要求摘要 + 附件对应关系
    作业/Homework 1/HW1.ipynb
    课件/Week 1/W1.pdf
    课件/Week 9/Supervise_Learning.ipynb
    其他/course_image/logo.png
```

### 文件怎么和作业对应上

两条依据,按优先级:

1. **作业描述里的文件链接**。老师把附件挂在作业说明里,HTML 里就是
   `/courses/200001/files/12345` —— 正则抠出来就是这个作业的附件,一点不猜。
   这些文件进 `作业/<作业名>/`。

   **这里有个坑,第一版就栽了:** 不能要求这个 id 出现在 `/courses/:id/files`
   列表里。老师直接上传到作业里的附件**不在那个列表**(实测 DS5110 的
   `HW1.ipynb` 就不在,22 个文件里没有它),而且有的课整个文件区是关着的
   (CS5800 的 `/files` 返回 403、一个文件都没有)。所以列表里查不到就按 id
   单查 `/files/<id>` —— 那条路一直是通的。修之前 5 门课的作业附件全是 0 个,
   修之后 CS5800 拿到 6 个、DS5110 拿到 1 个。
2. **模块结构**(`/modules?include[]=items`)。那是老师自己排的 Week 1/Week 2,
   同一个模块里的文件和作业天然相关。这些进 `课件/<模块名>/`。
3. 都不沾的进 `其他/`,带上 Canvas 里的文件夹名。

刻意**不做名字猜测**(HW1 对 W1.pdf?)—— 猜错了比没有更糟。

### 增量是怎么判断的

下完之后把本地文件的 mtime 设成 Canvas 的 `updated_at`。下次同步只要比这两个
时间,新的就重下,没变的一个字节都不传。实测:第一次 18 个文件 29.4 MB 用了
38 秒;第二次 2 秒、23 个全部跳过、零流量。

单个文件超过 80 MB 会跳过(课程里偶尔有几百 MB 的录像,不该默认拖下来)。
实测 DS5110 有 5 个 113~205MB 的课程录像,加起来 726MB。上限在设置里可调,
单个文件也可以在课程单页那一行点「仍然下载」强制要。

### 每个文件旁边都抽一份纯文本

同步时把 **PDF / DOCX / PPTX / ipynb** 的文字抽出来,写成同名的 `.txt` 放在
同一个目录:

```
CS5800/作业/Programming Assignment 1/
  Programming Assignment1 -Fa26.docx        原件(点「打开」用 Word 看)
  Programming Assignment1 -Fa26.docx.txt    纯文本
DS5110/课件/Week 9/
  W9.pdf
  W9.pdf.txt                                每页前面有 [p.N] 标记
```

两个不同的理由:

**docx/pptx 是必须的** —— Claude 的 Read 认 PDF、文本、图片,**不认 Office
格式**,而 CS5800 的作业要求就是 `.docx`。这两种是 zip + XML,所以抽取不依赖
第三方库(`zipfile` + 去标签 + `html.unescape`)。PA1 那份抽出 2219 字符,
"marked out of 10、worth 2%、due Sunday 9/27" 全在。

**PDF 是为了能搜。** Read 本来就能读 PDF,但**没法跨文件搜**。这一点是实测撞
出来的:问「所有课件里哪儿讲过 heapsort」,会话先去调技能脚本,而它在
Windows 上走的是 PowerShell 工具 —— 那条当时没在放行名单里,非交互会话又弹不出
确认框,于是被直接拒掉,它只能 Grep 纯文本文件,13 份 PDF 一个都搜不到,
自己在回答里写了「这个会话搜不了」。

有了 `.txt` 之后就不依赖任何脚本和权限了:`Grep` 一次扫完所有课件,
`Read` 那份 `.txt` 就有正文,而且 PDF 的页码标记还在。同一个问题再问一遍,
它搜了全部 23 份文本,给出了文件 + 行号级别的定位,还指出那份讲义是 part1、
HEAPSORT 的主循环不在里面。

PDF 抽取用 PyMuPDF(项目那个解释器里有);没有的话就只跳过 PDF,不影响其他。

## 两个技能

`.claude/skills/` 下两个,任何 Claude Code 会话(包括桌面应用里的对话)都能用:

| 技能 | 干什么 | 什么时候自动触发 |
|---|---|---|
| **course-files** | 查看/搜索课件和作业文件 | 问某份课件写了什么、要看 slides、作业要求全文、提到 `.pdf/.docx/.pptx` 路径、「哪节课讲过 X」 |
| **course-sync** | 手动同步一次课件 | 「新的 slides 下来了吗」、本地找不到某个文件、看上次同步时间 |

`course-files` 的正文写清了**优先走 `.txt` 副本**(Grep + Read,零权限),
脚本只在几个场合用:

```bash
coursedoc.py outline "W9.pdf"              # 22 页先看每页标题,再决定读哪几页
coursedoc.py read "W9.pdf" --pages 8-14    # 只要这几页
coursedoc.py find "heap sort"              # 空白不敏感:也能中 "Heapsort"
coursedoc.py list DS5110                   # 本地都有什么
```

两个脚本都会**自己挑解释器**:当前 python 缺 PyMuPDF / requests 时,换成
`data/pythonw-path.txt` 记的那个(库都装在那边)。用子进程换,不用
`os.execve` —— Windows 上那个是模拟的,实测在 Git Bash 里直接段错误(exit 139)。

### 权限这一步不能省

桌面应用里的对话是 `claude -p`,**非交互**,弹不出权限确认框 ——
需要确认的工具调用会被直接拒掉。所以 `.claude/settings.local.json` 里放行了
这两个脚本的命令前缀(Bash 和 PowerShell 两种写法),不是放行整个 shell:

```json
"Bash(python .claude/skills/course-files/scripts/coursedoc.py:*)",
"PowerShell(python .claude/skills/course-files/scripts/coursedoc.py:*)"
```

`install.ps1` 写的那份也一样,重装不会把权限冲掉。

## 邮箱子页面

标题栏左边多了一个 **学业 / 邮箱** 的切换(邮箱上有未读角标)。邮箱页左边是收件箱,
右边是**邮件简报**和**邮件对话** —— 和课业那套是**两份完全独立的历史**:

| | 课业 | 邮箱 |
|---|---|---|
| 简报存档 | `data/briefings.json` | `data/mail_briefings.json` |
| 对话存档 | `data/chats.json` | `data/mail_chats.json` |
| CLI 通道 | `chat` / `briefing` | `mailchat` / `mailbrief` |

四条通道复用同一条 SSE 连接,按 `channel` 分流 —— 所以课业简报在生成的时候,
你还能同时问邮件的事,互不打断。

邮件也能**拖到右栏**关联到对话(和作业、课件一样)。

### 只走 IMAP,Outlook 靠转发

**QQ / 163 / Gmail —— IMAP + 授权码。** QQ 不让用登录密码走 IMAP,要在邮箱设置里
单独生成一个 16 位「授权码」。**这一步只能你自己点**:QQ 邮箱 → 设置 → 账号 →
「IMAP/SMTP 服务」→ 开启 → 发短信验证 → 拿到授权码 → 填进设置里的「邮箱」那一节。
填完会立刻试登一次,登不上会把 IMAP 的原话显示出来(而且如果是 QQ,会额外提醒
"要的是授权码不是密码")。

**Outlook / 学校邮箱 —— 在 Outlook 里转发到 QQ。** 微软 2022 年起关掉了 IMAP 的
密码登录,只剩 OAuth;而 OAuth 要求先去 Azure 注册一个应用拿 `client_id`
(别人的 client_id 不能拿来用)。为了收几封信让人跑一趟 Azure,不值得 ——
这条路**做过又删了**。转发是一次设置、永久生效,这边只连 QQ 一个 IMAP 就全收到。

> **转发来的信按原始日期排。** 转发不改 `Date:` 头,所以一封三年前的旧信今天
> 被转过来,它在列表里还是落在三年前那个位置,不会冒到最上面。这不是没收到 ——
> 用「只看未读」或者按重要程度过滤更容易找到它。

凭据存在 `%USERPROFILE%\.canvas-helper\mail.json`,和 Canvas token 同一个目录
(装机时那个目录的 ACL 已经收紧到只有你本人可读写)。**不放在项目里** ——
项目目录是可能被整个打包发出去的。接口一律不回传密码和 token。

### AI 过目:一封信只过一次模型

每封信进来先被**过目一遍**:打标签、评重要程度、写一句「这封要我干什么」。
结果存在 `data/mail_ai.json`,按邮件 id 索引。

**这是整块设计的地基:同一封信的正文永远不进第二次 prompt。** 之后列表渲染、
按标签筛选、每天的简报,读的都是这份存档。所以钱是一次性花的 ——
Sonnet 实测 **83 封约 $0.33**(每封四分之一分钱),之后只有新到的信要过。
反过来的做法(每天把 60 封正文塞进简报 prompt)是每天都花、而且花的大半是重复。

调用形状是实测出来的:

```
claude -p --output-format json --model sonnet
       --system-prompt <两句话> --strict-mcp-config --restricted
```

- **prompt 走 stdin**,不走 argv。Windows 命令行上限 32767 字符,一批 25 封
  正文就能到 10KB,走 argv 早晚撞墙
- `--system-prompt` 把默认那套系统提示整个换掉;`--strict-mcp-config` 让它
  忽略 canvas 那个 MCP server(9 个工具的定义白占上下文);`--restricted`
  砍掉执行类工具。纯分类任务,不需要任何工具
- 一批 25 封 —— 固定开销(个人信息 + 标签目录 + 格式说明)约 800 字符,
  批越大摊得越薄,但太大了模型容易漏条
- 模型可换:设置里 Haiku / Sonnet / Opus 三档

### 四个级别 + 标签

级别 **要紧 / 留意 / 普通 / 噪音**(自己标了重点的另算一档「盯」)。
胸章是**图标 + 文字**(`◎盯` `▲留意` `·普通` `○噪音`),不靠颜色单独承载信息;
鼠标悬停能看到这一封**为什么**是这个级别。

标签**每封至少一个、最多三个**:学业 / 求职 / 工作 / 会议 / 住房 / 财务 /
行政 / 社交 / 广告 / 娱乐 / 出行 / 健康 / 验证码 / 系统通知。
都不合适的时候模型会自己造一个并收进目录 —— 实测它加了个「诈骗」,
给一封冒充官方要密码的钓鱼信用的,这个标签我自己没想到。
目录在设置里能加能删,而且会放进分析 prompt,所以改完目录新信就往新类上靠。

判定顺序:**自己标的重点 > AI 的结论 > 内置粗判**。最后那档只在分析还没跑到的
那几十秒里顶一下(第一次装上 83 封要跑一分多钟),胸章画成虚线框 ——
看得出"这还不是定论"。

### 坏标签和垃圾箱

设置 → 邮箱 → 标签目录是**两个框**:上面是普通标签,下面是「坏标签」。
把标签**拖到下面那个框**就设成坏标签,拖回上面就收回来。带坏标签的信
**不进收件箱**,收进垃圾箱 —— 邮件页左上角那个垃圾桶按钮切过去看,按钮上带
条数。**邮件本身一封都没动过**(这是本地的显示规则,不是服务器上的删除)。

第一版是每个标签上挂一个 🗑 小按钮,和旁边的 ✕ 挤在一起,又小又看不出是干什么的。
两个框加拖拽好在**状态一眼可见**:哪些是坏标签不用逐个看图标,看它在哪个框里。

实测把「广告」设成坏标签:收件箱 88 → 69 封,垃圾箱 19 封。

### 发件人分组:比标签高一级

**标签跟着信走,分组跟着人走。** 标签是 AI 每封判一次「这封是什么」;
分组是你一次认定「这个人是谁」,以后他发的每一封都算。开箱三档
**必看 / 好友 / 熟人**,可以加可以删。

分组按**地址**认人,不按显示名 —— 显示名是发信人自己写的,想改就改。

分了组有两个实际作用:

1. **他的信永远不会被坏标签藏进垃圾箱。** 这就是"高一级"的具体含义:
   规则可能判错,你对人的认定不会。导师用 Gmail 群发一封被判成「广告」的信,
   不能因为标签就给藏了
2. 邮件页顶栏能**按分组单独筛**,下拉里带每组的来信数

给谁分组:点开那封信,发件人旁边有个下拉。删掉一个分组时里面的人会一起移出去,
不留孤儿。存在 `data/mail_people.json`,和滚动缓存解耦 ——
"这是我导师"这件事得比 300 封的缓存活得久。

### 排序和筛选

| 轴 | 怎么用 |
|---|---|
| 排序 | 时间新→旧 / 时间旧→新 / 按重要程度(同级按时间) |
| 某一天 | 下拉里列出所有有邮件的日期 |
| 级别 | 所有 / 普通以上 / 留意以上 / 只看要紧的 |
| 标签 | 列表上方一排标签,带条数,点一下只看这一类;每封信自己的标签也能点 |
| 收件箱 / 垃圾箱 | 左上角垃圾桶按钮,带条数 |
| 发件人分组 | 所有人 / 必看 / 好友 / 熟人,下拉里带各组来信数 |
| 账号 / 未读 | 和以前一样(只有一个账号时账号下拉自己藏起来,给顶栏让位) |

**排序和筛选都在后端做。** 前端只拿 120 条,「按重要程度排」要是只排这 120 条,
第 121 条那封要紧的就永远排不进来。

### 一张卡片 = 固定的五段

顺序是定死的,扫列表的时候眼睛不用重新找:

```
Chen, Alex                                     ① 发件人,加粗,这一行只有它
邀请填写 Research Rush 兴趣表单,截止 9/21 10 点。 ② 一句话:这封要我干什么
[▲留意] [学业]                                  ③ 级别 + 标签
📎 兴趣表说明.pdf  3 KB                          ④ 附件
🔗 [表单]   neu.qualtrics.com/jfe/form/SV_abc   ⑤..n 链接,一行一条
🔗 [会议]   northeastern.zoom.us/j/123
🔗 [职位]   boards.greenhouse.io/x/jobs/1
还有 2 条链接
09-18 16:23  问 Claude                    ☆  ⌄  末行:时间、操作、盯、展开
```

**主题不在收起状态里。** 第二行那句总结就是替它的 —— 主题是发信人写给自己看的
(`Research Rush: Complete the interest form by Mon 9/21, 10 a.m.`),
总结是写给你看的("要我干什么")。主题在展开区最上面。
还没过目的那些没有总结,退回显示主题,标成斜体。

**每条链接前面有个短标签**说明这是什么。标签优先用正文里 `<a>` 的锚文本
(发信人自己写的"点这里干什么"),没有锚文本就按域名和路径猜类别 ——
表单 / 职位 / 会议 / 日历 / Canvas / 网盘 / 视频 / PDF / 主页 / 验证 /
订单 / 账单,都对不上就用域名。一长串带 query 的 URL 当标题是没法读的。

列表里链接最多列 6 条(一封营销邮件能抽出十几条,全铺出来卡片就成链接墙了),
多的折成「还有 N 条链接」,点一下直接进单封视图。

附件单击打开本地那个文件,**右键**打开所在文件夹。

### 左边那道竖线是什么意思

| 样子 | 含义 |
|---|---|
| **蓝线** + 发件人前面一个蓝点 | 未读 |
| **金线** + 淡橙底 + 末行实心 ★ | 你盯住了这封(简报每天提醒到你标完成) |
| 没有线 | 已读、也没盯 |
| 整条压暗 + 发件人加删除线 | 已经标过「完成」 |

这两种状态以前**都是蓝线**,长得一模一样,分不出是"没看过"还是"盯着的"。
现在颜色分开,而且未读多了一个实心圆点 —— 不靠颜色单独承载信息,
这是全项目一致的规矩。两种同时成立(未读又盯住)时金线优先:
盯住是你自己下的判断,比"还没看"更要紧。

### 在这儿读过,邮箱里也是读过的

点开一封信,**服务器上那封也会标成已读** —— QQ 网页版、手机上都同步。
设置 → 邮箱有开关,不想要就关掉。

> **这是整个应用唯一一处会改动你邮箱的操作。**
>
> 别的地方一律 `select("INBOX", readonly=True)`,连收邮件都是只读打开的;
> 只有这一个函数用可写的 SELECT,而且只动 `\Seen` 这一个标记 ——
> 不删信、不移动、不碰别的标记。
>
> 点错了在单封视图里能「标回未读」,服务器上也会真的改回去。
> 写失败(网络断了、授权码过期)就把本地状态退回去并把服务器的原话摆出来 ——
> 不会出现"这边显示已读、邮箱里还是未读"。

本地索引同步改掉,不用等下一轮轮询(3 分钟)界面才跟上;未读角标当场就变。

### 点开 = 占满左栏的单封视图

不是在卡片里就地展开 —— 那样列表会被撑得很长,读一封信还要在卡片缝里找。
点卡片任意空白处(或右下角 ›)进单封视图:**只接管左栏,右栏的对话照常在**,
问 Claude 的时候还能对照着看。

单封视图里有:返回按钮(或 `Esc`)、时间、问 Claude / 在网页打开 / ☆、
发件人和完整地址、**主题**、一句话总结、级别和标签、附件、**全部**链接、
以及全文(里面的 URL 高亮成可点的)。退出回列表时**滚动位置也还原** ——
翻到第 30 封点进去再出来,不会被扔回顶上。

后台每 3 分钟拉一轮邮件,拉完会刷列表;正在看单封的时候这个刷新不会把你踢回
列表,只是就地更新这一封。

### 超过 50 封分页

一页 50 封,底下一条**贴在底边**的分页条:`‹ [页码] / N 页 · 共 M 封 ›`。
中间那个框能直接输入页码,回车跳。

贴底是必要的:滚动条在整个面板上,分页条要是跟着滚,翻页得先滚到 50 封的最底下。

**切片是筛选和排序之后的最后一步。** 反过来的话,"按重要程度排"只会在当前
这 50 封里排,第 51 封那件要紧事永远翻不到前面。换筛选条件会自动回到第 1 页 ——
换完还停在第 7 页多半是空的。

### 附件是自动下到本地的

收信那一刻就存好了,按邮件日期分文件夹:

```
data/mail_files/2026-09-18/HW1.pdf
data/mail_bodies/<哈希>.txt      正文全文,一封一个
```

单个附件超过设置里的上限(默认 20MB)不自动下,卡片上把名字和大小列出来、
标成「太大没下」。正文**不进** `data/mail.json` —— 那是个每轮都整个重写的
滚动缓存,塞进正文等于每 3 分钟在硬盘上搬几 MB。

### 全文什么时候抓

**只给新到的邮件抓整封。** 轮询是 3 分钟一轮,要是每轮都把最近 40 封的
RFC822 重下一遍,那是几十 MB 的白流量。所以先用一趟 `(FLAGS RFC822.SIZE)`
把所有 UID 探一遍(便宜),只对**没见过的**下 `RFC822`;见过的只回报
读没读过,让本地索引原地更新。整封超过 25MB 的(基本是巨型附件)也不下全文,
退回老办法取头 + 4KB。

装这个功能之前就在本地的那些信只有头和摘要,链接和附件都是空的。
**后台补抓**会把它们补完:每收完一轮邮件顺手跑一批(一批 20 封、一轮上限 300),
取过的信不再取第二次。实测 78 封 44 秒,有链接的邮件从 8 封变成 77 封。
状态条上能看到「还有 N 封没取正文」,设置 → 邮箱有手动催的按钮。

整封超过 25MB 的(基本是巨型附件)不取正文,单封视图里直接说清楚。
这种信要**显式打上标记** —— 不打的话补抓每一轮都会重试它,进度永远差最后一封
(踩过)。

### 链接为什么要单独抽出来

正文里一串 `https://…?lipi=urn%3Ali%3Apage…` 是没法读的,但那个链接往往
**就是这封信要你做的事**(交表、看职位、确认预约)。所以单独列一行。

抽的时候做了三件事,不做的话列出来还不如不列(实测一封领英推送抽出 20 条,
前四条全是邮件顶部那排「动态/消息/人脉/通知」):

1. **砍掉追踪参数**(`utm_*` / `lipi` / `trk` / `fbclid` 这些),链接短得多,
   也更容易看出两条是不是同一个。只删已知的那些 —— 有的链接的 token 就在
   query 里,删错了那条就打不开了
2. **滤掉站点导航**:没有说明文字、指向的又是 `/feed/` `/notifications/`
   这种站点根路径的,那是邮件顶栏,不是内容
3. **有说明文字的排前面** —— 那些是正文里真写了"点这里干什么"的

正文和链接说明都是**发信人写的**,所以渲染从头到尾走 `textContent` 和 DOM
构造,一处 `innerHTML` 都没有。邮件里塞一段 `<img onerror=…>` 是很便宜的攻击。

### 盯住一封信,它就不会被忘掉

列表里点 ☆ 就是「盯住」。**之后每天的邮件简报都会点名提醒这封,并且带上盯了
几天,一直到你点「完成」。** 盯超过 3 天,设置里那条会变成橙色。

标注**单独存**在 `data/mail_flags.json`,不跟 `data/mail.json` 混 —— 后者是个
只留 300 封的滚动缓存,而你盯的那封信三周后可能还在盯。标注里连主题、发件人、
日期一起存了快照,所以**就算这封信早被挤出缓存,简报照样叫得出它的名字**。

设置 → 邮箱那一栏能看到「还在盯」的全部清单,每条带盯了几天,就地能标完成。

### 「我的情况」:一行一条事实

设置 → 邮箱最上面,左边名目、右边内容:

```
我的专业      数据科学(CS 研究生,2026 秋)
我的住址      (你住的那个公寓的名字)
我常用的软件  piazza、canvas、gradescope
我在找什么    2027 夏季数据科学实习
```

**刻意是键值对而不是一大段自述。** 填一行就多一条判断依据,写起来没负担;
模型读起来也不会把"我在找实习"和"我住在哪个公寓"揉成一团。名目随便加
(实验室、导师名字、在等哪封回信都行),留空的行不进 prompt。

这几行同时进两个地方:**AI 过目**和**每天的邮件简报**。效果是立刻能看出来的 ——
住址填了公寓的名字,那个公寓发来的通知就不再是陌生营销(实测被打上「住房」);
「我在找什么」填了,推送职位才分得清是机会还是噪音。

改完这里,已经判过的**不会**自动变。想让它按新信息重看一遍就点「全部重判」
—— 那要重新花一次钱,所以做成显式的按钮而不是自动触发。

以前这里有一段自由文本,外加两个关键词规则框(重要/屏蔽),删了:
AI 判级之后再留一套手写规则就是两个法官各判一遍,谁压谁说不清,
用户还得维护两处。想让某类邮件一律算噪音,写进「我的情况」就行。

### 新邮件多久能看到:十秒内

一条**长连接挂着,每 10 秒重 SELECT 一次 INBOX**,EXISTS 变大就立刻去取。
实测 **8.2 秒发现、11.2 秒进到本地索引**(这 11 秒里还包括下全文、抽链接)。
另外留着 120 秒一轮的完整轮询当兜底 —— 长连接被中间设备掐掉是常事。

这条路是试错出来的,记一下,免得以后有人再走一遍:

| 试过的 | 结果 |
|---|---|
| **IMAP IDLE** | **QQ 是个空头承诺**:CAPABILITY 里有 IDLE、命令也接受、`+ idling` 和 `IDLE terminated!` 都回,但**从不推送** —— 另一条连接 APPEND 成功后等 40 秒,一条 `EXISTS` 都没来 |
| **NOOP 探** | 同样什么都不说。对已经 SELECT 的会话,QQ 不通知新到达 |
| **重新 SELECT** | ✓ 同一条连接上再 SELECT 一次,EXISTS 立刻是新的,**只花 0.22 秒**(不用重登) |

支持真 IDLE 的服务器(Gmail、163)顺带还能更快:等待阶段会发一次 IDLE,
有推送就提前醒,没有就 10 秒后照常重 SELECT。

实现上有个坑:**别在 socket 上设超时、靠 `readline()` 抛异常来计时。**
imaplib 的 readline 读的是带缓冲的文件对象,超时一次之后状态就不对了,
后面再也读不到东西 —— 表现是状态一直停在"在等推送",服务器推了也收不到。
用 `select` 等可读(SSL 还要先问一次 `pending()`)。

### 收取和简报

长连接发现新信就取;另有 120 秒一轮的完整轮询兜底(设置里可关)。
只取信头和一段正文摘要(700 字),不下附件 —— 分析判断够用,
又不至于把上下文占爆。收完一轮就顺手把没过目的送去分析。

**邮件简报只播前一天的信。** 而且只放已经存好的那几行(级别 / 标签 / 一句话
摘要),不放正文 —— 正文在过目那一步已经读过一次了。实测 prompt 从
4493 字符降到 2067,而且里面没有任何一封信的原文。

生成简报之前会先收一轮邮件、再**等分析跑完**(最多 4 分钟)——
分析没跑完就播报,等于对昨天的邮件视而不见。

邮件简报每天一次,时刻单独设(默认也是 9:00)。规矩写在
[CLAUDE.md](CLAUDE.md) 的「邮件简报」一节:只说需要动手的,分「要回复 / 和课业
相关 / 其他」三类,账单验证码营销一律不提,15 行以内,而且要跟昨天那份对比。

## 对话历史

对话存在 `data/chats.json`,对话栏顶上那个下拉就是历史:选一段就能回看,
右边两个按钮是「新对话」和「删除」(删除要点两下,第一下变成"确认删除?",
3 秒内再点才真删 —— 无边框窗口里弹原生 `confirm()` 很突兀)。

**上下文怎么保证。** 两层:

1. 主路是 claude CLI 的 `--resume <session_id>`。每段对话都记着自己的
   session_id,切回哪段就续哪段 —— 这是真正的上下文,连工具调用都带着,
   而且不止 10 轮
2. CLI 的会话不保证一直在(清理、过期、换机器)。续不上时(带 `--resume`
   跑失败、而且一个字都没吐出来),自动清掉 session_id,把存档里的**最近
   10 轮**拼成一个 `<以往对话>` 块塞在问题前面重试一次 —— 起码不会失忆

所以「至少 10 轮」是下限,正常情况下是整段。

存档上限:40 段对话、单段 400 条消息,超了从最旧的删。点「新对话」时会顺手
把之前留下的空壳对话清掉,目录里不会攒一堆「新对话」。

`data/chats.json` 里有对话原文,和 `data/snapshot.md` 一样属于个人数据 ——
目录的 ACL 是跟着 `%USERPROFILE%\.canvas-helper` 一起收紧的那套,但这个文件
在项目目录下,注意别把项目整个发给别人。

## 每日简报

**一天一份,绝不重复。** 触发口径是「**每天 09:00 之后的第一次机会**」:

| 情况 | 行为 |
|------|------|
| 09:00 时应用正开着 | 调度线程当场生成 |
| 09:00 之后才开机 | 开窗时补一份 |
| 当天已有简报 | 任何路径都不再生成 |
| 09:00 之前开机 | 不播报,等到 9 点(或点「生成今日」) |
| 一天重启多次 | 只有第一次会生成 |

改时间:`briefings.py` 里的 `BRIEF_HOUR`。

**简报有历史。** 生成新简报时会把前 3 天的简报原文一起发过去,所以它说的是**变化**
而不是每天重念同一份清单:上次提醒过还没交的会点名「第 N 天还没动」、已经交了的
一句带过、新出现的标成新增。判断错了也会直接改口。

存档在 `data/briefings.json`(保留 60 天),用简报栏顶部的日期下拉翻看往日。
点「生成今日」可以手动重跑并覆盖当天存档。邮件简报同一套(`data/mail_briefings.json`)。

**打开看到的永远是最新那一份。** 只有正翻着往日存档的时候才停在你选的那天;
一旦切到对话栏、或者切去另一个子页面,回来就重新落到最新的。理由很简单:
翻历史是临时动作,不该变成粘住的状态。

实现上有个容易踩的顺序问题:`switchTab` 第一行就把 `state.tab = which` 写掉了,
所以"我是从别处切进来的吗"这个判断**必须先把旧值存下来**再赋值,不然条件
永远不成立、解钉那段代码一次都不会跑(就这么错过一轮)。同理,切子页面时
光把"钉住"标志清掉不够 —— 还得真的重拉一次目录,选中项才会被重算。

## 双端是怎么分的

**业务逻辑一行都没有分平台。** Canvas 客户端、邮箱、AI 过目、备忘录、课件同步、
简报、本地 HTTP 后端、整个前端 —— 全是纯 Python 和纯网页,两边跑的是同一份。
凭据路径本来就是 `~/.canvas-helper/`,两个系统同一个位置。

真正要分的只有**原生那一层**:一个无边框窗口、一颗自绘的悬浮球、一条自绘的
信息弹窗。这三件事在两个系统上是完全不同的 API,所以各有一个分发层:

| 分发层 | Windows | macOS | 干什么 |
|---|---|---|---|
| [native_window.py](native_window.py) | native_win32.py | native_cocoa.py | 操作自己那个窗口(34 个函数) |
| [orb_window.py](orb_window.py) | orb_win32.py | orb_cocoa.py | 悬浮球的**宿主** |
| [toast.py](toast.py) | toast_win32.py | toast_cocoa.py | 信息弹窗的**宿主** |
| [desktop.py](desktop.py) | — 同一个文件里按平台分支 — | | 深浅色、打开文件、自启目录、单实例 |

`server.py` 和 `app.py` 只 import 分发层,**不知道底下是哪一套**。

### 球和弹窗的样子是共用的,不是各画一遍

这是这次改造里最值得说的一点。[orb_render.py](orb_render.py) 和
[toast_render.py](toast_render.py) 是**纯 Python 逐像素算**的,一行平台代码都没有,
输出是**预乘 alpha 的 32 位像素**,打包成 `(A<<24)|(R<<16)|(G<<8)|B` 写进一个
uint32 数组 —— 小端机器上内存里的字节序就是 `B, G, R, A`。

而这个格式在两边都是原生的,不用转换:

| | 要什么 |
|---|---|
| Windows | `UpdateLayeredWindow` + `ULW_ALPHA` 要的就是预乘 BGRA 的 DIB |
| macOS | CGImage 的 `kCGImageAlphaPremultipliedFirst \| kCGBitmapByteOrder32Little` 同样是它 |

所以球在两个系统上是**同一颗球**,不是长得像。改一次配色、调一次阴影,两边一起变。
(实测过:重构前后逐像素比对,6 个尺寸、全部像素完全一致。)

宿主只负责两件事:**把那块内存交给系统去合成**,以及**写字**。

### 文字是唯一需要宿主帮忙的事

排版引擎没法共用 —— 断行规则、字体度量、省略号,只有系统自己算得对。所以分工是:

```
球的角标   渲染层填好红圆盘(纯 Python)-> 宿主把数字叠上去
弹窗       宿主先量出正文要几行高 -> 渲染层按这个高度画卡片底 -> 宿主写字
```

两边写字的手法刻意不同,因为两边的坑不同:

- **Windows** GDI 直接往 DIB 上画。**代价是它会把字形像素的 alpha 清零** ——
  不补回去那些像素在合成时是透明的洞,字就"看不见"。所以渲染层会交回一份
  alpha 遮罩,宿主写完字照着它把 alpha 补满
- **macOS** 根本不往裸内存里写字:球的角标由 NSView 在画完位图之后用
  `NSAttributedString` 叠上去,弹窗同理。少一大块容易出错的代码,而且文字由
  AppKit 渲染、自带 Retina 和字距 —— 上面那个 alpha 的坑在这边天然不存在

### macOS 那边的四个结构性差别

**一、句柄是 `windowNumber`。** 上层把句柄当一个不透明的 int 传来传去,所以
macOS 挑了 NSWindow 的 `windowNumber()` —— 也是个 int,而且能用
`NSApp.windowWithWindowNumber_()` 反查回 NSWindow。正因为两边都能用一个 int
表示,`server.py` 才一行都不用改。

**二、坐标统一成"原点左上、y 向下"**,也就是 Win32 那一套。Cocoa 原生是原点
左下、y 向上,翻转只发生在 `native_cocoa` 的两个辅助函数里。

这不是随便选的 —— 上层有真实的几何算术**默认 y 向下**,比如备忘录浮窗贴着球放:

```python
y = by - ph - 8        # 意思是"放在球的上方"
```

y 向下时 `by - ph` 更靠上,是对的;换成 y 向上,同一行就变成了"放在球的下方"。
这种错不会报异常,只会让窗口出现在离奇的位置。

**三、AppKit 只能在主线程上动。** 而这个应用的窗口操作全是从 Flask 的工作线程
发起的。Win32 的 `SetWindowPos`/`ShowWindow` 本来就为跨线程设计,直接调没问题;
AppKit 不是。所以 macOS 那边所有调用都转到主线程,而且**同步等结果** ——
因为上层有"写完立刻读"的代码:

```python
native_window.set_geometry(h, w, ht, anchor_br=anchor)
target = native_window.get_rect(h)      # 要读到刚设好的那个
```

异步投递的话这里会读到旧值,展开动画的起点就错了。

启动时序上还有个连带的坑:装球的那段跑在后台线程,而它要建 NSWindow ——
必须等 `webview.start()` 把 run loop 转起来,投过去的活儿才有人执行。所以
`setup_orb()` 在 macOS 上会先等一下 run loop(`native_cocoa.wait_for_main_loop`)。

**四、动画不能 sleep。** Win32 的球有自己一条线程,`time.sleep(POP_MS)` 睡的是
它自己。macOS 的球活在主线程上,一睡就把整个 run loop 堵住 —— WebView 会跟着
卡 150ms,能看出来。所以弹出/收起改成把帧排进队列,由一个 `NSTimer` 一帧一帧取。

手感的常数(`POP` / `GLOW_MS` / `HOVER_TWEEN` / 缓动曲线)两边是**照抄的**,
自检里也会比对缓动曲线是否逐点相同 —— 同一个应用在两个系统上手感不同是要避免的。

### 两个"缩放",别混用

| | 含义 | Windows | macOS |
|---|---|---|---|
| `dpi_scale(h)` | 逻辑尺寸 → 该平台的窗口单位 | DPI 比例(窗口 API 收物理像素) | **恒为 1.0**(Cocoa 用点) |
| `render_scale(h)` | 一个窗口单位画几个位图像素 | 同上,相等 | `backingScaleFactor`(Retina 是 2.0) |

Windows 上这两个数相等,所以以前只有一个函数也没出过问题;macOS 上必须分开 ——
混用的后果是窗口尺寸直接翻倍、或者球在 Retina 上糊成一团。窗口几何用前者,
球和弹窗的位图用后者。

### macOS 上还有一个坑:`isFlipped` 必须是 False

Quartz 里 CGImage 的第一行是图像的**顶**行,在非翻转的上下文里
`CGContextDrawImage` 画出来是正的。`OrbView` / `ToastView` 要是返回
`isFlipped() == True`,球会上下颠倒(左上那块高光跑到左下、投影跑到上面),
弹窗的阴影也会跑到上边。两个视图里都写了这个方法并注明原因,防止以后被顺手改掉。

### 装机和自启

| | Windows | macOS |
|---|---|---|
| 装机 | [install.ps1](install.ps1) | [install.sh](install.sh) |
| 卸载 | [uninstall.ps1](uninstall.ps1) | [uninstall.sh](uninstall.sh) |
| 自启 | 启动文件夹里的快捷方式 | `~/Library/LaunchAgents/com.neuhelper.gate.plist` |
| 闸门 | [startup-gate.vbs](startup-gate.vbs) | [startup-gate.sh](startup-gate.sh) |
| 手动开 | [launch.vbs](launch.vbs) | [NEU Helper.command](NEU%20Helper.command) |
| 图标 | `gui/icon.ico` | `gui/icon.icns` |

两个装机脚本是**六个步骤一一对应**的,可以并排读。几处 macOS 特有的讲究:

- **token 的权限**:Windows 那边是按 SID 的 `icacls`,macOS 是目录 700 + 文件 600
  (用 `umask 077` 创建,不然会继承当前 shell 的 umask)
- **不写 shell rc 文件**。Windows 的装机器会顺手设两个用户级环境变量;macOS 没有
  一个既持久、又能被 GUI/LaunchAgent 进程看到的等价物,所以干脆不设 ——
  `config.json` 本来就是主来源,环境变量只是覆盖用的
- **依赖多四个**:`pyobjc-core` / `pyobjc-framework-Cocoa`(窗口和视图)/
  `pyobjc-framework-Quartz`(位图合成)/ `pyobjc-framework-WebKit`(pywebview 用的
  WKWebView)。少一个就少一整块功能,所以自检里逐个点名
- **LaunchAgent 不能有 `KeepAlive`**。闸门在"今天已经开过"的日子会立刻退出,
  有 KeepAlive 的话 launchd 会疯狂重启它
- **PATH**。LaunchAgent 拿到的是极简环境,`python3` 很可能不在里面(Homebrew 在
  `/opt/homebrew/bin`)。装机时把解释器的绝对路径记在 `data/python-path.txt`,
  闸门先读它、读不到再去几个常见位置找。**找不到要报错,不能静默** ——
  这里踩过一次:记录的路径失效时,兜底循环没先清空变量,于是拿着那个坏值去 exec,
  用户看到的是一句晦涩的 "No such file or directory"
- **`.command` 而不是 `.sh`**:Finder 里双击 `.sh` 会用编辑器打开,`.command`
  才会在终端里跑。那个终端窗口没法避免,所以脚本起完应用就用 AppleScript
  把它关掉,只闪一下
- **`python` vs `python3`**:macOS 上通常没有 `python` 这个命令。两个技能的
  白名单里**两种都放了**(项目可能在两台机器之间同步,不能让两个装机脚本
  来回改写同一个文件),SKILL.md 里也注明了 macOS 上要写 `python3`

## 架构

```
startup-gate.vbs      开机守门:今天该不该开?该开就启动 GUI
startup-gate.sh       (macOS 是这个,由 LaunchAgent 调)
      │
      ▼
app.py                挑空闲端口 → 起 server 线程 → 开窗口
                      (Windows 是 WebView2,macOS 是 WKWebView,都由 pywebview 挑)
      │
      ├── server.py       Flask:仪表盘 / 简报 / 窗口 / 偏好 / SSE / 静态文件
      │     ├── canvas_api.py     只读 Canvas 客户端(分页、HTML 转文本、时区)
      │     ├── briefings.py      简报存档 + 09:00 调度
      │     ├── chat_bridge.py    包装 claude CLI 的流式输出
      │     ├── native_window.py  纯 Win32 的窗口操作(形变、拖拽、最大化、显隐)
      │     └── orb_window.py    悬浮球:自己画的分层窗口(独立线程 + 消息循环)
      │
      └── gui/            前端:index.html + app.css + app.js

canvas_mcp.py         独立的 MCP stdio server,给所有 Claude Code 会话用
```

三个设计决定,都是踩坑之后定的:

**不用 pywebview 的 js_api 桥,改成本地 HTTP + SSE。** 那个桥每次调用的返回值都要
跨线程 marshal 回 WebView2 的 UI 线程,而 WebView2 的 COM 对象只允许 UI 线程访问。
低频调用没事,聊天流式增量的高频往返会把窗口**卡死成「未响应」**。改成 `fetch` +
`EventSource` 之后,走的是浏览器自己的网络栈,热路径上一次 marshal 都没有。

**窗口操作走 HTTP + 纯 Win32,完全不挂 js_api。** 一开始想用 pywebview 的
js_api 桥做窗口几何操作(频率很低,以为没问题),结果一挂上窗口就卡死成
「未响应」。控制其余变量做了对照:不挂 `responding=True`、挂上 `responding=False`,
frameless / min_size / easy_drag 三个参数在简单页面上八种组合全部正常,所以罪魁
祸首就是桥本身。现在改成后端用 `SetWindowPos` / `ShowWindow` / `PostMessage` ——
这几个 API 本来就是为跨线程调用设计的,从 Flask 的工作线程调是安全的。

唯一不能这么省事的是拖拽:`WM_NCLBUTTONDOWN` + `HTCAPTION` 那条捷径在这里
**完全拖不动**(捕获在 Chromium 的子窗口手里),只能自己跟光标 ——
理由写在上面「拖窗口」那节。

**接口带 token 校验,但只守 `/api/*`。** 静态文件不能守:`index.html` 里的
`<link href="app.css">` 是相对路径,解析出来不带 `?k=`,一守就 403,整个前端会退化
成无样式的裸 HTML。要保护的是会吐个人数据的接口。

**开机用 pythonw.exe + 窗口样式 1。** 样式 0(隐藏)会把标志写进子进程的
STARTUPINFO,WinForms 让第一个窗体沿用了它 —— 结果是隐藏控制台的同时把应用窗口
一起隐藏了(窗口创建成功但 `visible=False`)。pythonw 压根没有控制台,配样式 1
既没有黑窗也没有这个副作用。

## 安装器改了系统的哪几处

两个装机脚本都只动这几个地方,对应的卸载脚本一一撤销:

| 位置 | Windows | macOS |
|------|---------|-------|
| 凭据 | `~/.canvas-helper/config.json`,ACL 锁到你的 SID | 同一个文件,目录 700 + 文件 600 |
| 环境变量 | 用户级 `CANVAS_API_TOKEN` / `CANVAS_BASE_URL` | **不设**(见下) |
| Claude Code 用户级 MCP 配置 | 名为 `canvas` 的 stdio server | 一样 |
| 自启 | 启动文件夹 `NEU Helper.lnk` → `startup-gate.vbs` | `~/Library/LaunchAgents/com.neuhelper.gate.plist` → `startup-gate.sh` |
| 桌面 | `NEU Helper.lnk` | `~/Desktop/NEU Helper.command`(软链接) |
| 解释器路径 | `data/pythonw-path.txt` | `data/python-path.txt` |

**macOS 上刻意不设环境变量。** 没有一个既持久、又能被 GUI/LaunchAgent 进程看到的
等价物 —— 要么改 shell rc 文件(装机器不该偷偷改你的 `.zshrc`),要么再装一个
plist。而 `config.json` 本来就是凭据的主来源,环境变量在这个项目里只是覆盖用的,
所以直接不设。

重新安装(比如换了 token):

```powershell
# Windows
powershell -ExecutionPolicy Bypass -File install.ps1 -Token "14523~新token"
```

```bash
# macOS
./install.sh --token "14523~新token"
```

不带 token 重跑会复用已存的那个,并且会把 Canvas 连通性、MCP 握手、桌面后端
全部自检一遍。macOS 那边还会额外确认四个 pyobjc 包在不在、以及原生层 import
得动 —— 缺一个的话在这儿就看出来了,而不是第一次开窗口才发现。

## 两个开机开关

**每天只开一次 → 每次开机都开**

| | 改哪儿 |
|---|---|
| Windows | [startup-gate.vbs](startup-gate.vbs) 里 `oncePerDay = True` 改成 `False` |
| macOS | [startup-gate.sh](startup-gate.sh) 里 `ONCE_PER_DAY=1` 改成 `0` |

两边判定依据都是 `data/last-launch.txt` 里的日期,删掉这个文件就会在下次登录
重新打开。(简报本身另有一天一份的限制,所以多开几次也不会多生成简报。)

**临时不想要**

| | 怎么关 |
|---|---|
| Windows | 删掉启动文件夹里的 `NEU Helper.lnk` |
| macOS | `launchctl bootout gui/$(id -u)/com.neuhelper.gate`,或者直接删掉那个 plist |

桌面上那个照常能手动开 —— 两边都是"开机那条走闸门、桌面那条直接开应用",
指向不同的东西。

## token 安全

- token 存在用户目录下(`~/.canvas-helper/`),**没有**写进项目文件,所以这个
  文件夹可以安全地传给别人或推到 git。**两个平台同一个位置**,换机器就拷这一个目录
- 权限两边都收紧了:Windows 是按 SID 的 ACL,macOS 是目录 700 + 文件 600
  (`umask 077` 创建,不然会继承当前 shell 的 umask)。`selfcheck.py` 在 macOS 上
  会真去读一遍权限位,不是假设
- 本地 HTTP 服务只监听 `127.0.0.1`,端口随机,接口还要带一次性 token
- 但 token 对同一个登录账号下的任何进程都是可读的 —— 这是本地凭据的固有性质
- **这个 token 曾经出现在聊天记录里,建议换一个**:
  Canvas → Account → Settings → Approved Integrations 删掉旧的、New Access Token
  生成新的,然后用上面的命令重跑安装器
- `uninstall.ps1` 只清本地,**不会**吊销 Canvas 那边的 token,得自己去删

## 出问题时

先跑自检,它会告诉你哪一环断了:

```
python selfcheck.py          # Windows
python3 selfcheck.py         # macOS
```

再不行就重跑装机脚本(它自己也带一轮自检):

```powershell
powershell -ExecutionPolicy Bypass -File install.ps1    # Windows
```

```bash
./install.sh                                            # macOS
```

| 现象 | 原因 |
|------|------|
| 开机没反应 | 看 `data/app.log`;或 `data/last-launch.txt` 已是今天(删掉重试) |
| 窗口白屏 / 没样式 | 静态文件被 403 了,检查 `server.py` 的 token 校验范围 |
| 工具报 401 | token 失效或被撤销,重新生成后重跑安装器 |
| `claude` 里看不到 canvas 工具 | 会话是安装前开的,重启 Claude Code |
| 简报一直不出来 | 没到 09:00,或当天已生成过;点「生成今日」强制跑 |
| 窗口卡死「未响应」 | 检查有没有人给 `create_window` 加回了 `js_api=` |
| 悬浮球点不开 | 看 `app.log` 里有没有「悬浮球就绪」;没有就是 `orb_window` 初始化失败 |
| 球拖丢了 | 设置里「把球放回右下角」;或者删掉 `data/prefs.json` 里的 `orbX/orbY` |
| 界面发卡 / 闪 | 设置里把玻璃模糊调到 0、过渡动画关掉,先排除这两项 |
| 文字看不清 | 整窗透明度调回 100%(那一项连文字一起透);或者把表面不透明度提上去 |
| 球一直在转有点费电 | 设置里关掉「过渡动画」,光晕会冻住、定时器也不留 |
| 收放看着有断点 | 量一下 `GetWindowRect`:窗口末尾尺寸应该等于球本体(默认 46px 物理),差很多就是 `min_size` 把它卡住了 |
| 对话接不上上文 | 看回答里有没有「会话续不上,重开一段再试」——那是 CLI 会话没了,已经自动重试 |
| 对话报「退出码 1」 | 现在会自动重试一次;还是失败的话 `data/app.log` 里有 `[chat]` 那行,带 returncode、stderr 和 stdout 尾巴 |
| 邮箱一封都收不到 | 设置 → 邮箱,看账号那一行的报错。QQ 最常见的是填了登录密码而不是**授权码** |
| 转发来的新邮件像是没收到 | 转发不改 `Date:` 头,所以它按**原始日期**插队,不在列表最上面。「只看未读」能看到 |
| 历史里一堆空「新对话」 | 点一次「新对话」就会清掉它们 |
| 课件没同步下来 | 看设置里「自动同步到本地」开没开;或者点「立即同步」看进度和报错 |
| 某门课一个文件都没有 | 老师可能把文件区和模块都关了 —— `/courses/:id/files` 返回 403,这时候那一栏就是空的 |
| 对话里说"搜不了课件" | 看 `data/downloads` 下有没有 `.txt` 副本;没有就同步一次(PDF 抽文本要 PyMuPDF) |
| 技能里的脚本跑不起来 | 非交互会话拒了 shell 调用 —— 不用管,Grep + Read 那些 `.txt` 效果一样 |
| 窗口拖不动 | 看 `/api/window/drag/*` 有没有被调到(开 `CANVAS_HELPER_HTTPLOG=1`) |
| MCP 显示连不上 | `claude mcp list` 看状态;手动跑 `python canvas_mcp.py` 看 stderr |

macOS 上还有这几种:

| 现象 | 原因 |
|------|------|
| `bad interpreter: /bin/bash^M` | 那个 `.sh` 被换成 CRLF 行尾了。`sed -i '' 's/\r$//' 脚本名` 修掉,以后在 Windows 上编辑要留意编辑器 |
| 双击 `.command` 没反应 | 没有执行位。`chmod +x "NEU Helper.command"`(装机脚本会加,手动拷过来的不会) |
| 开机没自动开 | `launchctl list \| grep neuhelper` 看在不在;`data/launchagent.log` 里有闸门的输出 |
| 登录后闪一下就没了 | 大概是找不到 `python3`。LaunchAgent 的 PATH 极简,看 `data/python-path.txt` 指的解释器还在不在 |
| 窗口出来了但没有球 | `data/app.log` 里找「悬浮球就绪」。没有的话看有没有「主线程 run loop 没起来」——那是 pywebview 没转起来 |
| 球是个方块 / 有白边 | `OrbView.isFlipped()` 被改成 True 了,或者 `setOpaque_(False)` 丢了 |
| 球上下颠倒(高光在左下) | 同上,`isFlipped` 必须是 False |
| 弹窗串色(偏蓝/偏红) | CGImage 的 `kCGImageAlphaPremultipliedFirst \| kCGBitmapByteOrder32Little` 被改了,那两个标志和渲染层的字节序是配套的 |
| 报 `No module named 'AppKit'` | 四个 pyobjc 包没装齐,重跑 `./install.sh` 或者 `pip3 install pyobjc-core pyobjc-framework-Cocoa pyobjc-framework-Quartz pyobjc-framework-WebKit` |
| 界面偶尔卡半秒 | 窗口操作是转到主线程同步等的,主线程被什么堵住了。`app.log` 里会有「主线程 2.0s 没响应」那行 |
| 技能里的脚本报找不到 python | macOS 上通常只有 `python3`。白名单里两种都放了,让它用 `python3` 就行 |

`data/app.log` 是关键:开机是用 pythonw 启动的,没有控制台,所有输出都落在这里 ——
**前端的 JS 异常也会上报到这里**(`[client]` 开头),否则界面出问题会完全无迹可寻。

两个排障用的环境变量:

| 变量 | 作用 |
|------|------|
| `CANVAS_HELPER_MODE=orb` | 直接以某个形态启动(orb / chat / full) |
| `CANVAS_HELPER_FRAMED=1` | 退回带系统边框的窗口 |

诊断 MCP server 最直接的办法是手动喂它一条 JSON-RPC:

```powershell
'{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-06-18","capabilities":{},"clientInfo":{"name":"x","version":"1"}}}' | python canvas_mcp.py
```

## 卸载

```powershell
# Windows
powershell -ExecutionPolicy Bypass -File uninstall.ps1
powershell -ExecutionPolicy Bypass -File uninstall.ps1 -KeepToken   # 保留 token
```

```bash
# macOS
./uninstall.sh
./uninstall.sh --keep-token
```

两边都是:撤掉自启、注销 MCP、删掉 Canvas token、清空 `data/` 缓存。
项目文件不会被删,想彻底清掉自己删文件夹。

**邮箱凭据刻意留着**(`~/.canvas-helper/mail.json`)—— 重装之后邮箱还是配好的。
但"我已经卸载了"不该悄悄在硬盘上留一个邮箱授权码,所以 `uninstall.sh` 会把这件事
说出来并告诉你那个文件在哪。两边都**不会**吊销 Canvas 那边的 token,得自己去
Approved Integrations 删。

`.cmd`、`.vbs`、`.ps1` 三种文件**刻意保持纯 ASCII**:Windows 会用系统 ANSI 代码页
(中文系统是 GBK)去解码它们,写中文进去会变成乱码。所有中文都放在 Python、
JS 和 Markdown 里,这些是按 UTF-8 读的。

`.sh` 和 `.command` 里的**提示文字也是纯 ASCII**,不过理由不同:装机脚本可能在
一个编码不由我们决定的终端里跑,一份乱码的安装日志比一份朴素的更难查问题。
代码注释里也一样(那几个文件的注释是英文的,和 `install.ps1` 一致)。

**这两类文件的行尾也不一样,别搞混:** `.vbs` / `.ps1` / `.cmd` 是 CRLF,
`.sh` / `.command` **必须是 LF** —— 带 `\r` 的 shebang 在 macOS 上会得到
`bad interpreter: /bin/bash^M`,四个脚本一个都跑不起来。在 Windows 上编辑它们
要留意编辑器有没有顺手换成 CRLF。
