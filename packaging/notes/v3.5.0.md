# v3.5.0 —— 托盘图标；开机时小球终于认主题了

## 任务栏右下角多了个小图标

左键把窗口叫回来，右键是菜单：打开 / 展开完整面板 / 收成悬浮球 / **退出**。

**它存在是因为三态里有一态整个主窗口是隐藏的。** 收成悬浮球之后，球要是被拖到
了屏幕边缘、或者手快连点两下收进了角落，除了任务管理器就没有别的出路。

macOS 上它在**菜单栏右侧**——那边没有"任务栏通知区"这回事，菜单栏才是它的
对应物。功能和回调是同一套；按 macOS 的惯例，左键也是弹菜单（所以"打开"是
菜单的第一项，而不是绑在左键上）。

三个不显然的地方：

- **Explorer 重启之后图标会自己加回去。** 通知区被清空时系统广播一条
  `TaskbarCreated`，不听这条的话图标就永远消失，而进程还活得好好的。
  加回去这一步做成了**幂等**的（加不上就先删一次再加）——上一个实例崩溃留下的
  "幽灵图标"也能覆盖掉
- **退出时主动把图标摘掉。** 不摘的话通知区会留一个点不动的东西，一直挂到
  你把鼠标划过去、系统才发现那个进程早没了
- **菜单里的回调丢到另一个线程跑。** 那是托盘自己的消息循环，回调要切形态、
  要等窗口动画——在循环里同步做完的话，这段时间托盘对系统就是"没响应"，
  右键会卡住

菜单文案跟着界面语言走（原生菜单不是网页，`gui/i18n.js` 那套 DOM 翻译够不着，
所以和右下角弹窗一样在 Python 这边分岔）。

## 修：重启之后小球又变回默认那颗

选了 NEU / 海边 / 像素的人，每次开机看到的都是最初那颗蓝球，**除非去动一下
直径**才会变成对的。

原因是顺序错了一步。球在**构造函数里**就把所有帧画好了（弹出/收起的缩放帧、
光晕的相位帧，四十来张），而拨主题这件事发生在球建完之后：

```
app.py:  o = OrbWindow(...)          ← 这时候画的,用的是默认配色
         server.attach_orb(o)        ← 到这儿才 set_theme
```

而 `set_look` 只在**直径 / 深浅 / 缩放 / 动画开关**变了的时候才重画 —— 换主题
这四样一个都不变。所以那颗默认配色的球会一直留到你去动直径为止，正是用户描述
的现象。

现在建球之前先 `sync_art_theme()`。`attach_orb` 里留了一道兜底（漏调了就强制
重画一次），代价只是多渲染一次。

顺手量了一下，四档主题画出来的球哈希互不相同——这个 bug 之前没人量过，
所以它能活这么久。

## In English

**A tray icon.** Bottom-right notification area on Windows; the right side of the
menu bar on macOS (there is no "notification area" there — the menu bar is its
counterpart). Left-click brings the window back; right-click gives you Open /
Expand / Collapse to the orb / **Quit**.

It exists because one of the three window modes hides the main window entirely.
Once collapsed to the orb, if the orb ends up dragged to a screen edge or
double-clicked into a corner, Task Manager was the only way out.

Three details worth knowing: the icon **re-adds itself after Explorer restarts**
(the shell broadcasts `TaskbarCreated`; ignore it and your icon is gone forever
while the process lives on) and that re-add is idempotent, so a ghost icon left
by a crashed instance gets taken over; the icon is **removed on quit** so no
dead icon lingers; and menu callbacks run on their own thread, because doing
them inside the tray's message loop would make the tray unresponsive for as long
as a window animation takes.

**Fixed: the orb went back to the default look after every restart.** If you had
picked NEU / Beach / Pixel, every launch showed the original blue orb until you
nudged the diameter. The orb renders all of its frames *in the constructor*, and
the theme was only applied afterwards — while `set_look` only repaints when
diameter / dark / scale / animation change, none of which a theme switch touches.
The theme is now set before the orb is built.
