# v3.5.1 —— 发布流水线修好了；顺带把 3.4.0 / 3.5.0 的内容一并交代

## 先说这一版为什么存在

**v3.4.0 和 v3.5.0 的代码都推上去了，但一个 Release 都没发出来。** tag 在、
提交在、CI 也没标红 —— 就是没有安装包。所以那两版的更新说明没人看得到，
这一份把它们合并在一起。

原因是两个坑叠在一起：

1. **`macos-13` 这个 runner 已经不存在了。** GitHub 下线了 Intel 的 macOS
   构建机。我在 3.4.0 里把它写进了矩阵想顺手出 Intel 的包 —— 那条腿两次运行里
   压根没出现过（job 列表里只有 `macos (macos-14)`）
2. **job 级别的 `continue-on-error: true` 不管 `needs`。** 我以为它的意思是
   "这个 job 挂了不影响别人"，**错了** —— 它只是不把整个 run 标红，那个 job 的
   conclusion 仍然是 failure，于是 `needs` 它的 `publish` 照样被**跳过**

两条一起的后果是最坏的那种：mac 那条腿一挂，`publish` 直接不跑、一个包都不发，
**而 run 看着还不红**。

现在 `publish` 用 `if: always()` 自己判门，只要 Windows 那个包成了就发；
而 macOS 不再 `continue-on-error` —— 它挂了 run 就是红的（该看见的要看见），
但发布照走。

**Intel Mac 因此没有预构建包**，只能在本机跑一次 `./packaging/build_mac.sh`。
点「检查更新」现在会把这句话直接说给你，而不是干巴巴一句"没有本平台的安装包"。

以下是 v3.4.0 和 v3.5.0 的内容，都在这一版里。

## 邮件搜索：敲一个字就有结果

页面顶上那一条。搜发件人、主题、AI 摘要和标签，**不用打完一句再点搜索**。

做法不是"每敲一下发一次请求"。可搜字段一次性拿到前端（进邮箱页时就开始拿，
和你想第一个关键词的时间完全重叠），之后每次按键都只是一次内存过滤 ——
**零请求、零等待**。实测 3000 封的量级下：

| | 耗时 |
|---|---|
| 建一次索引（只在拿到数据时做） | 4ms |
| 每次按键的过滤 + 排序 | **0.16–0.32ms** |

远在一帧（16.7ms）以内。三个刻意的取舍：haystack 只拼一次（不在每次按键里
`toLowerCase` 三千遍）；渲染限前 200 条（过滤三千条是微秒级的事，把三千个
DOM 节点塞进页面才是真卡）；一帧只画一次（按键事件比帧还密）。

搜索时**忽略其它筛选** —— 在搜「验证码」的人不会希望它还被「只看未读」或者
某个标签挡着。多个词是"与"关系。Esc 或 ✕ 清空。

## 未读永远排在已读前面

「按重要程度排」的时候，**已读的「要紧」也比不过未读的「普通」**。原来是把
已读折成 0 级，那样它还能和未读的「噪音」按时间混排 —— 一封刚到的已读信仍然
会插到未读前面。现在"未读还是已读"是第一顺位，级别只在未读里面比。

## 一键已读 / 每封信上的「标回未读」

- 筛选那一排多了「全部标已读」，**两步确认** —— 它一次动几百封、动的是服务器上
  的标记，没有撤销。按账号分组批量发一条 IMAP STORE（一次登录搞定一个账号，
  而不是一封一次；QQ 邮箱对频繁登录会限流，循环调的话几十封之后就全失败）
- 每张卡片上都有「标已读 / 标回未读」。原来只有单封视图里那一个，想把一封刚
  扫过的信标回未读得先点进去再退出来

## 收成悬浮球快了一倍，而且点下去就动

整套形变从 **580ms 压到 280ms**（45 淡出 + 165 形变 + 70 交接），帧数跟着减
（165ms 里打 26 帧是 6ms 一帧，`SetWindowPos` 根本跟不上）。

「按钮有滞后」那一半是另一个原因：点击之后原来要 `await` 一帧再发请求，本意是
让淡出先画出来，可后端自己就先等 45ms，那一帧纯属白等。顺手量了本机 loopback
的延迟（p50 1.7ms / p90 14ms），所以**没有**去动服务器协议 —— 滞后跟网络无关。

## 任务栏右下角多了个小图标

左键把窗口叫回来，右键是菜单：打开 / 展开完整面板 / 收成悬浮球 / **退出**。
macOS 上它在**菜单栏右侧**（那边没有"通知区"这回事）。

**它存在是因为三态里有一态整个主窗口是隐藏的。** 收成悬浮球之后，球要是被拖到
了屏幕边缘、或者手快连点两下收进了角落，除了任务管理器就没有别的出路。

- Explorer 重启后图标会自己加回去（系统广播 `TaskbarCreated`，不听这条的话
  图标就永远消失而进程还活着），而且这一步是**幂等**的 —— 上个实例崩溃留下的
  "幽灵图标"也能覆盖掉
- 退出时主动把图标摘掉，不留点不动的东西

## 修：重启之后小球又变回默认那颗

选了 NEU / 海边 / 像素的人，每次开机看到的都是最初那颗蓝球，**除非去动一下
直径**。

顺序错了一步：球在**构造函数里**就把四十来张帧画好了，而拨主题发生在球建完
之后；而 `set_look` 只在直径 / 深浅 / 缩放 / 动画开关变了时才重画 —— 换主题这
四样一个都不变。现在建球之前先拨主题。

## macOS 的打包版现在也会自动更新

原来点「更新」只打开下载页。现在两个平台都是自动的，只是换法不同：Windows
逐个文件换进安装目录（**exe 放最后** —— 前面任何一样没拷成，回滚之后还是完完
整整的旧版）；macOS **换整个 `.app`**（不能拆着换：那会破坏 bundle 的封印，
而 Apple 芯片上连 ad-hoc 签名都是执行的前提）。

macOS 那条路两个不显然的地方：`data/` 和 `CLAUDE.md` 在 bundle 里面
（`Contents/MacOS/`），整包换掉之前必须先搬进新 bundle，不然一次更新就把你的
邮件、对话、课件、设置全清了；暂存目录必须在 bundle **外面**
（`~/.canvas-helper/update`），放里面的话一挪旧 bundle 就把暂存、以及正在跑的
那个安装进程自己的可执行文件一起挪走了。解压用 `ditto` 而不是 Python 的
`zipfile`（后者不还原执行位和符号链接，解出来的 `.app` 是死的）。

换失败会回滚：旧版本原样留在 `NEU Helper.app.old`，改个名就能用回去；而且应用
下次启动会在学业页顶上说出来。**这条路仍然没有在真机上验证过。**

## 顺带修掉两个 macOS 上必然触发的 bug

- `native_cocoa.animate_rect` 少了 `alpha_from` / `alpha_to` 两个参数，而
  `server.py` 的 `collapse()` 一直在传 —— **macOS 上「收成悬浮球」必然抛
  TypeError**。它发生在后台线程里，表现是点了按钮窗口纹丝不动、日志里也看不见
- 自检里因此加了一条**签名对账**（第 22 项）：用 ast 静态比两端同名函数的参数，
  不一致就报出来。它又抓出两处（`animate_to` 的 `anchor_br` 只有 cocoa 有、
  `set_window_icon` 的参数名两边不同），都对齐了

## In English

**Why this release exists: v3.4.0 and v3.5.0 were pushed but never published.**
The tags and commits are there, CI was not even red — there were simply no
packages. Two traps stacked up:

1. **The `macos-13` runner no longer exists** (GitHub retired Intel macOS
   runners). I added it to the matrix in 3.4.0 to also ship an Intel build; that
   leg never appeared in either run.
2. **Job-level `continue-on-error: true` does not help dependents.** It only
   keeps the *run* from being marked failed — the job's conclusion is still
   `failure`, so anything with `needs:` on it is **skipped**.

Together: the mac leg failed, `publish` never ran, nothing was released, and the
run did not look red. `publish` now gates itself with
`if: always() && needs.windows.result == 'success'`, and macOS is no longer
`continue-on-error`, so a mac failure turns the run red while the release still
goes out. **Intel Macs therefore have no prebuilt package** — run
`./packaging/build_mac.sh` once locally; Check for Updates now says exactly that
instead of a bare "no package for your platform".

Everything from v3.4.0 and v3.5.0 ships here: **mail search** (results on the
first keystroke — the index is fetched once and every keystroke is an in-memory
filter; 0.16–0.32ms per keystroke over 3000 messages), **unread always sorts
above read**, **mark all read** and **mark-as-unread on every card**,
**collapsing to the orb is twice as fast** (580ms → 280ms, and the wasted frame
before the request was removed), a **tray / menu-bar icon** with quick quit,
**the orb finally honours your theme at startup** (it was rendering all its
frames in the constructor, before the theme was applied), and **packaged macOS
builds now self-update** by replacing the whole `.app`. Also fixed a TypeError
that made "collapse to orb" fail on every Mac, and added a dispatch-layer
signature parity check to self-check so that class of bug cannot hide again.
