# v3.3.2 —— Release 里第一次有 Mac 的包（未验证）

## macOS：有包了，但请当成 beta

这一版起，CI 会在 macOS runner 上构建一个 Apple 芯片的 `.app`，
附件叫 `NEU-Helper-mac-arm64.zip`。

**必须先说清楚三件事：**

1. **没有人在真机上打开过它。** 作者手上只有 Windows。业务逻辑两端是同一份，
   窗口/悬浮球/弹窗那一层的 Cocoa 实现也一直在仓库里（函数一个不缺，我核对过），
   但"代码对得上"和"打开就能用"是两回事
2. **没有签名。** 第一次打开要右键 →「打开」，或者去「系统设置 → 隐私与安全性」
   放行一次。压缩包里的 `README.txt` 写了步骤
3. **Intel Mac 用不了这个包。** PyInstaller 冻的是构建机的解释器和原生库，
   换架构就跑不起来 —— Intel 机器请自己跑 `./packaging/build_mac.sh`

起不来的话开个 issue，贴上 `NEU Helper.app/Contents/MacOS/data/app.log`。

另外 macOS 的**打包版不会自动更新**：替换 `.app` 的流程同样没法在 Windows 上
验证，所以点「更新」只会打开下载页。源码版（git clone）没这个限制。

## 顺带：3.3.1 那两道新闸在 macOS 上是空的

上一版加的「更新前先查装在哪」只想着 Windows：

- `where_problem` 只认 `TEMP` / `TMP` 两个环境变量，而 macOS 和 Linux 那边叫
  `TMPDIR` —— 于是那道"你在压缩包里直接跑"的闸在非 Windows 上**等于不存在**
- 它还排在了"是不是 macOS"的判断**前面**。macOS 整条自动更新路本来就不走，
  结果装在 `/Applications` 的人会先撞上一句"装不进去"，而真正该说的是
  "手动更新，已经帮你打开下载页"

Windows 用户装这一版没有任何行为变化。

## 发布流水线拆成了三个 job

原来 publish 是 Windows 那个 job 的最后一步；加 macOS 之后必须拆开，否则没法
等两边都出包。**macOS 那个 job 是 `continue-on-error` 的** —— 那一档是新的、
未验证的，它挂了不该把 Windows 的包一起拖住。真挂了的结果就是 Release 里只有
win 的 zip，和加它之前一样；而少了 Windows 包会直接让发布失败。

## In English

**The Release now ships a macOS build — please treat it as a beta.**

CI builds an Apple-silicon `.app` on a macOS runner and attaches it as
`NEU-Helper-mac-arm64.zip`. Three things have to be said plainly:

1. **Nobody has opened it on a real Mac.** The author only has Windows. The
   business logic is one shared codebase and the Cocoa side of the window /
   orb / toast layer has always been in the repo (every public function is
   there — I checked), but "the code lines up" is not "it launches".
2. **It is unsigned.** First launch needs right-click → Open, or one pass
   through System Settings → Privacy & Security. `README.txt` in the zip
   spells it out.
3. **Intel Macs cannot use this build.** PyInstaller freezes the interpreter
   and native libraries of the build machine — run
   `./packaging/build_mac.sh` yourself on an Intel Mac.

If it does not start, please open an issue with
`NEU Helper.app/Contents/MacOS/data/app.log`.

Packaged macOS builds also **do not self-update**: replacing a `.app` is the
one path that cannot be verified from Windows, so Update just opens the
download page. Running from source (git clone) has no such limit.

**Also fixed: the two new guards from 3.3.1 were dead on macOS.** The
"check where you are installed before updating" check only looked at `TEMP` /
`TMP`, but macOS and Linux call it `TMPDIR` — so the "you are running from
inside the zip" guard did nothing off Windows. It also ran *before* the
is-macOS check, so someone installed in `/Applications` would be told "cannot
install" instead of "updating is manual here, the download page is open."
Nothing changes for Windows users.
