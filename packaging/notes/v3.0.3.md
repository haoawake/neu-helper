# v3.0.3 —— 「更新并重启」真的会重启了,外加开机自启的开关

## 1. 点了更新并重启,应用就没了

Windows 上这个按钮**从来没成功过**。日志里是这一句：

```
更新后重启:等了 20 秒锁还占着,放弃
```

单实例用的是命名互斥体。新进程带 `--after-update` 起来时会重试等锁，因为旧进程
还在收尾 —— 这段逻辑是对的，注释里还写着「打包版那条路踩过这个坑」。

问题出在拿锁那一行：

```python
h = k32.CreateMutexW(None, False, name)
if h and k32.GetLastError() == 183:   # ERROR_ALREADY_EXISTS
    return False                       # ← 没关句柄
```

`CreateMutexW` 在「已存在」时照样返回一个**有效句柄**（指向同一个互斥体）。
不关掉，就等于自己给它续命。平时无所谓 —— 判完马上就退了；但重试是**循环**的：
第一次失败漏一个句柄，之后哪怕旧进程早退干净，互斥体也被**自己漏出来的句柄**
撑着。于是每一次重试都必然失败，等满 20 秒放弃。

双进程量过：不关句柄等满 10 秒拿不到，关了 3.1 秒就拿到。

## 2. 设置里能勾开机自启了

以前只有一个「打开启动文件夹」，要自己进去看有没有那个快捷方式。现在
设置 → 通用 → 窗口 里有个**开机自动打开**的开关，直接建 / 删那一项
（Windows 是启动文件夹里的快捷方式，macOS 是 LaunchAgent 的 plist）。

两个细节：

- **状态每次现问操作系统**，不存进 `prefs.json`。这件事的真相在系统那边 ——
  你可能自己去启动文件夹删掉了，偏好里再存一份布尔值只会和现实打架
- 开关按**后端回的实际状态**摆，不是按你点击的意图摆。建快捷方式可能失败
  （启动文件夹被组策略锁了之类），那时候它会弹回去，而不是显示成「开着」骗你

它指向的仍然是**闸门**而不是应用本身：闸门每天只放行一次，重启几遍也只会
弹一个窗口。

## In English

**"Update and restart" now actually restarts.** On Windows it never worked:
`CreateMutexW` hands back a valid handle even when the mutex already exists, and
the single-instance check returned without closing it. The restart path retries
in a loop, so after the first failed attempt the new process was holding the
mutex alive *itself* — every later retry failed too, and after 20 seconds it gave
up. From the outside: you click update and the app is just gone.

**Settings now has an "Open at login" switch.** It creates or removes the login
item directly (a Startup shortcut on Windows, a LaunchAgent plist on macOS)
instead of making you go dig in the folder. The state is read from the OS every
time rather than cached in prefs, and the switch follows what actually happened,
not what you asked for.
