# v3.1.0 —— 邮件摘要只说事,验证码直接给,弹窗点了就开信

三条都冲着同一件事:**右下角那条弹窗，看一眼就够，不用再开邮箱。**

## 1. 摘要不再替你做判断

原来给模型的指令是「summary 一句话说清**这封信要我干什么**」，于是写出来的是一堆

> 需要你在 9/21 前回复 · 建议关注 · 此邮件无需处理 · 值得留意

有没有用、要不要动手，这些你自己会看。摘要现在只写**这封信在说什么**：

- 不加「需要你…」「建议…」「无需处理」这类判断和催促
- 不复述主题，不客套
- 有具体的数字、日期、金额、地点就**写进去** —— 摘要的价值全在这儿。
  「9/21 10 点前交表单」比「提醒你尽快完成」有用一百倍

## 2. 验证码直接写在摘要开头

这种信的全部价值就是那几位数字，让人再点开一次是白费事。现在会写成

```
验证码 123456,GitHub 登录用
```

右下角那条弹窗显示的就是 summary —— 所以验证码会**直接出现在弹窗上**，
瞟一眼就能填。快递、账单、订单同理:单号、金额、送达时间都写进去。

## 3. 弹窗点一下直接打开那封信

以前点它只是把窗口叫回来，还得自己去邮箱里翻。现在：

- 一次只进来**一封**新邮件 → 点弹窗直接打开那一封
- 一次进来好几封 → 点弹窗回邮箱列表（点开某一封不一定是你想看的那封）

弹窗本来就能接收点击（更新提醒那条一直可以点），只是新邮件那条从来没给过
跳转目标。

> 已经过目过的邮件**不会**回头重写摘要 —— 一封信只过一次模型，结果存档复用。
> 想让存量邮件按新规则重来，设置 → 邮箱 → 「全部重判」（要再花一次钱）。

## In English

All three changes serve one goal: **the corner toast should be enough on its own.**

**Summaries stop judging for you.** The prompt used to ask for "what this mail
wants me to do", which produced a lot of "you need to reply by…", "worth noting",
"no action required". You can see that yourself. A summary now just says what the
mail *is*, with the concrete number, date, amount or place written into it.

**Verification codes go straight into the summary** — `验证码 123456, for GitHub`.
The toast shows the summary, so the code lands in the corner of your screen and
you never open the mailbox. Same for tracking numbers, amounts and delivery times.

**Clicking the toast opens that mail.** One new message: it opens that one. Several
at once: it takes you to the list, because guessing which one you meant is worse.

Already-triaged mail keeps its old summary — one model pass per message, cached.
Settings → Mail → "Re-judge everything" redoes them (costs again).
