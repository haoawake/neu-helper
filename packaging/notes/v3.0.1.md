# v3.0.1 —— 代理没开也能更新

只修一件事，但它会挡住源码版的每一次更新。

## 现象

点「更新并重启」，报：

```
更新没成功:RuntimeError: git fetch 失败:fatal: unable to access
'https://github.com/haoawake/neu-helper.git/': Failed to connect to
127.0.0.1 port 7897 after 2108 ms: Could not connect to server
```

7897 是 Clash 之类代理的本地端口。奇怪的地方在于：**明明平时是直连的，
浏览器也能上 GitHub。**

## 为什么

git 认的是 `http.proxy` / `https.proxy` 这两条**配置**，和环境变量、和你此刻
能不能直连都没关系。在国内配过代理的人，这两条多半一直写在全局 git 配置里：

```
git config --global --get-regexp proxy
http.proxy   http://127.0.0.1:7897
https.proxy  http://127.0.0.1:7897
```

代理开着的时候它是快路；代理没开，每一条 git 网络操作都会先去敲那个端口，
敲不开就整条失败。而报错里只字不提「这是你自己配的代理」—— 从用户那头看
就是「更新坏了」。

## 改了什么

更新时如果栽在「代理连不上」，**自动绕过代理重试一次**：

- 只作用于那一条命令（`git -c http.proxy= -c https.proxy= fetch …`），
  **不动你的配置** —— 代理开着的时候那条配置是对的，不该被悄悄抹掉
- 两次都失败才报错，而且把**两次**的原文都给出来。只报后一半的话，你会以为
  自己压根没配代理
- 「检查更新」那条路（数落后几个提交）同样处理

顺带把应用里「改了什么」的截断上限从 2000 提到 6000 字符 —— 一篇像样的更新
说明轻松过两千字，截在 2000 会把正文腰斩。

## 也可以自己去掉

如果你已经不用那个代理了，直接删掉更省事：

```
git config --global --unset http.proxy
git config --global --unset https.proxy
```

---

## In English

**One fix: updating no longer breaks when your proxy is off.**

Git reads `http.proxy` / `https.proxy` from its own config — not from the
environment, and not from whether you happen to have a direct connection right
now. If you ever set up a local proxy (Clash and friends put it on 127.0.0.1),
that config line usually stays forever. With the proxy running it is the fast
path; with the proxy off, every git network operation dies on
`Failed to connect to 127.0.0.1 port 7897`, and the error says nothing about
the proxy being yours.

The updater now retries once with the proxy bypassed for that single command.
Your config is left alone — it is correct whenever the proxy is actually up.
If both attempts fail you get both error messages, not just the second one.
