# v3.4.0 —— 邮件搜索、一键已读、收放快一倍，macOS 也能自动更新了

## 邮件搜索：敲一个字就有结果

页面顶上那一条。搜的是发件人、主题、AI 摘要和标签，**不用打完一句再点搜索**。

做法不是"每敲一下发一次请求"。可搜字段一次性拿到前端（进邮箱页时就开始拿，
和你想第一个关键词的时间完全重叠），之后每次按键都只是一次内存过滤 ——
**零请求、零等待**。

实测 3000 封的量级下：

| | 耗时 |
|---|---|
| 建一次索引（只在拿到数据时做） | 4ms |
| 每次按键的过滤 + 排序 | **0.16–0.32ms** |

远在一帧（16.7ms）以内。三个刻意的取舍：

- **haystack 只拼一次**，不在每次按键里 `toLowerCase` 三千遍
- **渲染限量**（前 200 条，多的说一句"还有 N 封"）—— 过滤三千条是微秒级的事，
  把三千个 DOM 节点塞进页面才是真卡
- **一帧只画一次** —— 按键事件比帧还密

搜索时**忽略其它筛选**：在搜「验证码」的人不会希望它还被「只看未读」或者某个
标签挡着。多个词是"与"关系。Esc 或者 ✕ 清空。

## 未读永远排在已读前面

「按重要程度排」的时候，**已读的「要紧」也比不过未读的「普通」**。

上一版是把已读折成 0 级，那样它还能和未读的「噪音」按时间混排 —— 一封刚到的
已读信仍然会插到未读前面。现在"未读还是已读"是第一顺位，级别只在未读里面比；
已读之间不再比级别（反正都知道了），按时间新旧排。

## 一键已读 / 每封信上的「标回未读」

- 筛选那一排多了「全部标已读」，**两步确认** —— 它一次动几百封，动的是服务器上
  的标记，没有撤销。按账号分组批量发一条 IMAP STORE（一次登录搞定一个账号，
  而不是一封一次登录；QQ 邮箱对频繁登录会限流，循环调的话几十封之后就全失败）
- 每张卡片上都有「标已读 / 标回未读」。原来只有单封视图里那一个，想把一封刚扫过
  的信标回未读得先点进去再退出来。标回去是有用的动作 —— 未读排在所有已读前面，
  等于"这封我还得回来处理"

## 收成悬浮球快了一倍，而且点下去就动

整套形变从 **580ms 压到 280ms**（45 淡出 + 165 形变 + 70 交接），帧数跟着减
（165ms 里打 26 帧是 6ms 一帧，`SetWindowPos` 根本跟不上，白发一半）。

「按钮有滞后」那一半是另一个原因：点击之后原来要 `await` 一帧再发请求 ——

```js
await new Promise((r) => requestAnimationFrame(r));   // 删掉了
```

本意是让淡出先画出来，可后端自己就先等 45ms，那一帧纯属白等。顺手量了一下本机
loopback 的延迟（p50 1.7ms / p90 14ms），所以**没有**去动服务器协议 —— 滞后跟
网络无关，全在动画预算里。

## macOS 的打包版现在也会自动更新

原来点「更新」只会打开下载页。现在两个平台都是自动的，只是第 4 步分岔：

| | 怎么换 |
|---|---|
| Windows | 逐个文件换进安装目录，**exe 放最后** —— 前面任何一样没拷成，回滚之后还是完完整整的旧版 |
| macOS | **换整个 `.app`**。不能拆着换：那会破坏 bundle 的封印，而 Apple 芯片上连 ad-hoc 签名都是执行的前提 |

macOS 那条路有两个不显然的地方，都写在代码旁边了：

- **`data/` 和 `CLAUDE.md` 在 bundle 里面**（`Contents/MacOS/`）。整包换掉之前
  必须先搬进新 bundle，不然一次更新就把你的邮件、对话、课件、设置全清了
- **暂存目录必须在 bundle 外面**（`~/.canvas-helper/update`）。放里面的话，一挪
  旧 bundle 就把暂存、以及正在跑的那个暂存进程自己的可执行文件一起挪走了
- 解压用 `ditto` 而不是 Python 的 `zipfile` —— 后者不还原执行位和符号链接，
  解出来的 `.app` 是死的

换失败会回滚：旧版本原样留在 `NEU Helper.app.old`，改个名就能用回去；而且应用
下次启动会在学业页顶上说出来（那张「我打算变成哪一版」的纸条）。

**Intel Mac 现在也有包了。** CI 加了 `macos-13`（Intel）那一档，附件是
`NEU-Helper-mac-x86_64.zip`；Apple 芯片仍然是 `NEU-Helper-mac-arm64.zip`。
只发 arm64 的话，Intel 机器的「检查更新」会永远报「这个版本没有本平台的安装包」。

**还是那句话：macOS 这条路没有在真机上验证过。** 我只有 Windows。

## 顺带修掉一个 macOS 上必然触发的 bug

`native_cocoa.animate_rect` 少了 `alpha_from` / `alpha_to` 两个参数，而
`server.py` 的 `collapse()` 一直在传 —— 于是 **macOS 上「收成悬浮球」必然抛
TypeError**。它发生在后台线程里，表现是点了按钮窗口纹丝不动、日志里也看不见。

这类"分发层两边签名走偏"的问题没法靠读代码发现，所以自检里加了一条**签名对账**
（`python selfcheck.py`，第 22 项）：用 ast 静态比两端同名函数的参数，不一致就
报出来。顺手把另外两处也对齐了（`animate_to` 的 `anchor_br` 只有 cocoa 有、
`set_window_icon` 的参数名两边不同）。

## In English

**Mail search — results on the first keystroke.** A search box at the top of the
mailbox page, over sender, subject, AI summary and tags. It is not
request-per-keystroke: the searchable fields are pulled once (starting the moment
you open the mailbox page) and every keystroke is a pure in-memory filter —
**no request, no wait**. Measured at 3000 messages: building the index once takes
4ms, each keystroke's filter+sort takes **0.16–0.32ms**, well inside one frame.
Rendering is capped at 200 rows (filtering 3000 is microseconds; inserting 3000
DOM nodes is what would actually stutter). Search ignores the other filters —
someone searching for a verification code does not want "unread only" still in
the way.

**Unread always sorts above read.** Under "by importance", a read *Important*
mail now loses to an unread *Normal* one. The previous version folded read mail
to level 0, which still let it interleave by time with unread *Noise*.

**Mark all read** (two-step confirm; one batched IMAP STORE per account rather
than one login per message), and **Mark as unread on every card** — marking
something back to unread is a real action now that unread always sorts first.

**Collapsing to the orb is twice as fast** — 580ms → 280ms, with frame counts
scaled down to match. The other half of "the button feels laggy" was an
`await requestAnimationFrame` before the request was even sent; it is gone. I
measured local loopback latency first (p50 1.7ms / p90 14ms) and therefore did
**not** touch the server protocol — the lag was never the network.

**Packaged macOS builds now self-update.** Windows swaps files into the install
directory (exe last, so a partial failure rolls back to a completely intact old
version); macOS **replaces the whole `.app`** (you cannot swap files inside a
bundle — it breaks the seal, and on Apple silicon even an ad-hoc signature is a
prerequisite for execution). Two non-obvious points, both now written down next
to the code: `data/` and `CLAUDE.md` live *inside* the bundle and must be carried
into the new one first, and the staging directory must live *outside* the bundle
or moving the old bundle takes the staging copy — and the running installer's own
executable — with it. Failures roll back to `NEU Helper.app.old`, and the app
says so on next launch. **Intel Macs now get a build too**
(`NEU-Helper-mac-x86_64.zip`). This path is still unverified on real hardware.

**Also fixed: a bug that was guaranteed to fire on macOS.**
`native_cocoa.animate_rect` was missing the `alpha_from` / `alpha_to` parameters
that `server.py` has always passed, so collapsing to the orb raised a TypeError
— inside a background thread, so the window simply did not move and nothing was
logged. Self-check now includes a **signature parity check** across the three
dispatch layers, which also caught two more drifts.
