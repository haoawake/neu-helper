# v3.3.1 —— 「更新说成功了，重启还是旧版本」

有人从 3.2.0 点更新，界面说装好了 3.2.3，重启回来还是 3.2.0，反复如此。

## 先说结论：机制本身没坏

我拿真的 3.2.0 和 3.2.3 的包端到端跑了一遍替换流程 —— 6 个项目全拷成，exe
确实换成了新的，装好的那一份也正常拉起来了。所以问题不在换文件这一步。

真正的原因，几乎一定是**你跑的那一份不在你以为的地方**。最常见的两种：

1. **在压缩包里直接双击 exe。** Windows 允许这么干 —— 它偷偷把 zip 解压到
   `%TEMP%\Temp1_NEU-Helper-win-x64.zip\` 再运行。更新确确实实写进了那个
   目录，可你下次再从压缩包打开，又是**原样解压一份旧的**出来。
   每次都"更新成功"，每次都还是旧版本
2. 解压在了 Program Files 之类当前用户写不进去的地方

**怎么办**：把 zip 里那个 `NEU Helper` 文件夹**整个拖出来**放到你自己的目录
（比如「文档」），从那儿启动，再更新。

## 为什么它之前一声不响

这是这一版真正要修的东西。替换文件的活**不是**发起更新那个进程干的 ——
是下载下来的新版 exe 自己干的（Windows 不让覆盖正在运行的 exe，所以只能让
新的那份等旧的退出，再把自己拷过去）。而旧进程在那之前就 `os._exit(0)` 了：

```
旧进程：下载 → 解压 → 起新版 exe → 说"正在重启…" → 自杀
                                    ↑ 从这以后它什么都不知道了
新进程：等旧的死 → 拷文件 → 拉起来        （成没成，没人问）
```

所以不管后面发生什么，用户看到的都是"正在重启…"。四个改动：

- **点之前先查装在哪。** 目录写不进去、或者在系统临时目录里（= 从压缩包里
  直接跑），当场说清楚并且**不下载** —— 25MB 下完了也只是白下，而且下完
  进程就退了，那时候再报错根本没人看得见
- **确认新版 exe 真的起来了再退。** 原来是 `sleep(1.2)` 就自杀。杀毒软件拦下
  这个没签名的 exe，用户得到的是"点了更新，应用没了"，一个字的解释都没有。
  现在新版 exe 一启动就打个招呼，等到了才敢退；等不到就报错、**不退**
- **记一张纸条，重启之后对账。** 退出前写下"我打算变成 3.2.3"。装好的那一份
  启动时拿自己的版本号去比：对得上就撕掉纸条，对不上就在学业页顶上挂一条
  橙色横幅，写明"你点的是 v3.2.3，现在跑的还是 v3.2.0，装在 ⟨路径⟩"，
  外加一个「打开安装目录」的按钮 —— 让你自己看一眼那是哪儿，比解释一百句管用
- **exe 放到最后拷。** 版本号是从 exe 里读的，它一换这次更新就"生效"了。
  所以它必须是最后一步：前面任何一样没拷成，回滚之后应用还是完完整整的旧版。
  另外回滚时那些合并拷贝的目录退不回去，日志现在会照实说出来，不再假装干净

## In English

**"The update said it worked, but after restarting I'm still on the old
version."**

The replace mechanism itself is fine — I ran the real 3.2.0 → 3.2.3 packages
end to end: all six items copied, the exe was replaced, the installed copy
relaunched. The cause is almost always that **the copy you run is not where you
think it is**, and by far the most common case is **double-clicking the exe from
inside the zip**. Windows lets you do that: it quietly unpacks to
`%TEMP%\Temp1_...zip\` and runs from there. The update really does land in that
folder — and then opening the zip again unpacks the old one on top. Every
attempt "succeeds"; every restart is the old version.

**Fix:** drag the whole `NEU Helper` folder out of the zip into somewhere you
own (Documents), start it from there, then update.

**Why it never said anything** is the real bug, and this release fixes it. The
process that swaps the files is not the one you clicked in — it is the newly
downloaded exe installing itself (Windows will not let you overwrite a running
exe). The old process calls `os._exit(0)` before any of that happens, so it can
never report the outcome. Four changes:

- **Check where you are installed before downloading.** Not writable, or inside
  the system temp folder (= running from the zip) → say so immediately and skip
  the 25 MB download, because once it finishes the process exits and nobody
  would see the error anyway.
- **Confirm the new exe actually started before exiting.** It used to
  `sleep(1.2)` and quit. If antivirus blocked the unsigned exe you got "I
  clicked update and the app vanished," with no explanation. The new exe now
  says hello the moment it starts; the old one waits for that, and refuses to
  exit if it never comes.
- **Leave a note and reconcile after the restart.** The installed copy compares
  its own version against what was intended. Mismatch → an orange bar on the
  Study page: "you asked for v3.2.3, this is still v3.2.0, installed at ⟨path⟩",
  with an *Open the install folder* button.
- **Copy the exe last.** The version number comes from the exe, so swapping it
  is what makes an update "take". If anything earlier fails, the rollback now
  leaves you with a completely intact old version.
