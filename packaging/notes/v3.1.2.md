# v3.1.2 —— 点完弹窗窗口不再赖在最上层

接着 3.1.1。那一版让「点弹窗不再把窗口缩小」，改成只把窗口抬到最前面。
结果抬完就赖着不走了 —— 完整面板一直压在所有窗口上面，要手动缩一次才恢复。

## 为什么

抬窗口用的是 `native_window.show()`，它里面是：

```python
user32.SetWindowPos(hwnd, HWND_TOPMOST, ...)   # 蹭一下置顶，保证露头
user32.SetForegroundWindow(hwnd)
```

后台进程直接调 `SetForegroundWindow` 常被 Windows 拒掉，所以先蹭一次
`HWND_TOPMOST`。问题是这一下**不撤**：窗口从此就是置顶窗口了。

这个坑代码里早有注释警告过 —— 从悬浮球还原那条路后面就跟着一句
「置顶必须在这里再定一次」。我 3.1.1 新加的那条路忘了抄。

## 改了什么

`show()` 之后把置顶按你的设置重新定一次：

| | 钉了大头针 | 没钉 |
|---|---|---|
| 完整面板 | 置顶 | **不置顶** |
| 对话框 | 置顶 | 置顶（那一态本来就是浮着问两句的） |

---

## In English

Follow-up to 3.1.1. That release stopped the toast from shrinking your window and
raised it to the front instead — but it then stayed pinned above everything until
you resized it by hand.

Raising uses `native_window.show()`, which nudges the window to `HWND_TOPMOST`
first because a background process calling `SetForegroundWindow` is usually
refused by Windows. That nudge is never undone, so the window stays topmost
forever. The orb-restore path already re-applies the correct topmost state right
after — the new path added in 3.1.1 forgot to. It does now.
