# v3.0.4 —— 版本那一行:当前多少、最新多少,一眼看全

## 现象

点「现在检查」，出来这么一句：

```
当前 v3.0.2 · 代码已是 v3.0.2,重启生效
```

同一个号说了两遍，等于没说。

## 为什么

那一行原来是按状态各拼各的话，「重启生效」那一支写的是
`当前 v{current} · 代码已是 v{latest}`。

坑在 `latest` —— 它是 **GitHub Release** 的版本号。可「代码已是」说的明明是
**磁盘上**那份（`disk_version`，后端一直有给，前端没用）。平时两者不一样还看不
出问题；刚发完版、Release 和磁盘同步了，两个数就撞成一个。

## 改了什么

不再按状态拼不同的话。**两个版本号永远都摆出来**，后面才跟一句「该怎么办」：

```
当前 v3.0.2 · 最新 v3.0.3 —— 重启生效
当前 v3.0.2 · 最新 v3.0.3 —— 可以更新
当前 v3.0.3 · 最新 v3.0.3 —— 已是最新
当前 v3.0.3 · 最新 v3.0.3 —— 源码落后 3 个提交
当前 v3.0.3                        （还没查过）
```

- **当前**取跑着的这个进程里的版本
- **最新**取 Release 和磁盘里**更大的那个** —— 源码版的磁盘可能比任何 Release
  都新（刚 pull 过、或者自己改过）
- 比大小是按数字段比的，不是字符串：`3.0.10` 排在 `3.0.9` 后面

横幅里那句「代码已经更新到 vX」也跟着改成读磁盘版本，不再读 Release 的。

---

## In English

The version line used to say things like `now v3.0.2 · code is already v3.0.2,
restart to apply` — the same number twice, which tells you nothing. The second
number came from the **GitHub release**, while "the code is already at" refers to
what is **on disk**; those are usually different, but right after a release they
collide.

Now both numbers are always shown, with the action after them:

```
now v3.0.2 · latest v3.0.3 - restart to apply
now v3.0.2 · latest v3.0.3 - update available
now v3.0.3 · latest v3.0.3 - up to date
```

"latest" is whichever is greater, the newest release or what is on disk — a
source checkout can be ahead of every release. Versions are compared per numeric
segment, so 3.0.10 sorts after 3.0.9.
